## 1. 摘要

- 架构风格：两端在同一局域网内工作，连接分监听方和拨号方：监听方运行 HTTP 服务和控制通道，拨号方连接并编排传输（[ADR-0004](../decisions/ADR-0004-symmetric-listener-dialer-roles.md)）。设备间控制走 WebSocket，文件内容走 HTTP。电脑和 Android 都能作监听方或拨号方，任意两台设备之间可以互传。
- 当前实现：双向覆盖复制（移动端或电脑都能发起）、写入前全量备份、本机恢复，以及游戏、设备和传输界面。传输时可选择删除目标多出的条目。有限桥不传文件字节。接口边界见[接口约定](api-contracts.md)。
- 核心模块：设备与地址管理、目录映射、当前目录预览、本次差异计划、文件流传输、平台文件适配。
- 关键约束：明文 HTTP、手选方向、无历史同步基线、目录不递归汇总大小。
- 已选技术栈：React + TypeScript + Vite；Windows 使用 Tauri（系统 WebView）+ Node sidecar + Ant Design；Android 使用 Capacitor + Ant Design Mobile，文件能力使用 Java 原生插件。双端框架选择见 [Q-001](../requirements/open-questions.md)。
- 技术选型理由：共用业务模型、协议和纯业务规则；按 [ADR-0002](../decisions/ADR-0002-ui-library-and-shared-rendering.md)，与两端交互差异无关的展示组件和页面主体也放 `@savedata-sync/shared/ui`，平台交互、页面状态与 Hooks 由各端维护。移动端优先 antd-mobile，使用 antd 时同样检查触控区域；两套组件库分别配置，颜色与圆角取同一套 CSS 变量。
- 平台差异：Windows 使用 Node.js 文件与 HTTP 能力；Android 使用 SAF、ContentResolver 和原生文件流，不将 content URI 当成本地绝对路径。
- 风险：SAF 属性及写入能力因提供者而异；自动发现受局域网组播条件影响。

## 2. 架构原则

| 原则 | 说明 |
| --- | --- |
| 配置与地址分离 | 本地生成并保存稳定安装设备 ID；地址只作为可更新的连接信息。同步项目引用设备 ID 和本地目录配置，不以 IP 或 MAC 作为主键 |
| 明文 HTTP | 不部署 TLS、证书或数据加密。连接后核对设备 ID 并保存设备关联 |
| 当前状态决定操作 | 每次任务重新读取两端目录，仅结合本次方向与复制模式生成计划；不读取或维护历史共同基线、历史哈希或历史增量索引 |
| 预览不执行写入 | 浏览与刷新读取当前条目；显示采集时间及未知状态；真正执行前重新校验可能变化的条目 |
| 文件夹不汇总大小 | 目录大小列建议显示“—”，不递归汇总后代文件字节数；修改日期读取目录自身元数据。同步枚举后代文件不属于目录大小计算 |
| 界面与平台能力分离 | apps 下分 mobile、desktop、shared；模型、业务规则和与平台交互无关的渲染放 shared，平台交互、页面状态和 Hook 各端实现。两端文件始终并列，列内布局按列宽切换 |
| 文件以流传输 | 文件内容通过 Node.js 或 Android 原生流读取和发送，避免将整份文件转为 Base64 跨 JS 桥传递 |
| tar.gz 流式传输 | 双向统一把本次待传文件边读边打包为 tar.gz，经分块 HTTP 原生流发送；接收端边收边解包到私有目录，内容收齐后逐文件写入目标，逐项报告结果 |
| Android 活动传输 | 业务不判断前后台；仅用户显式发起的传输通过持续通知/dataSync 前台服务保持，Activity 销毁后原传输继续，完成/显式取消及清理后退出。本机服务开着时由 `connectedDevice` 前台服务和常驻通知保持监听，用户关掉才停；进程结束后不自动重启，再打开应用时服务保持关闭。普通操作不处理切后台后的成败，不引入自动同步或旧任务重放 |
| 独立备份 | 备份可开启、默认关闭，每个游戏保留 1–4096 份（默认 10 份）；目标端备份区位于同步目录之外，不参与方向或差异判定 |
| 任务安全边界 | 同一时间只有一个写入任务；内容先解包到私有区，收齐后才写入目标，失败时报告实际结果；SAF 不能原子替换整个目录 |

## 3. 模块概览

| 模块 | 职责 | 边界 | 状态 |
| --- | --- | --- | --- |
| 设备与连接 | 初次关联、保存设备 ID、更新地址、重连 | 监听方广播并显示连接二维码，拨号方用发现列表、扫码（只在移动端）或手动 IP 连接，改址时自动重连。当前已实现桌面端的广播、二维码、发现列表、手动 IP 和重连，Android 一侧的发现列表、扫码、手动 IP 和重连 | active |
| 同步项目 | 保存项目名称、可选展示信息和两端目录映射 | 配置不保存历史文件索引；任务固定项目映射与两端目录关联 | active |
| 预览与比较 | 读取当前条目、属性对照、生成本次差异计划 | 共用 TypeScript 模型，原生适配只负责实际读取 | active |
| 桌面端应用 | 桌面界面、目录选择、HTTP 服务、复制与恢复 | Node sidecar 运行后端，Tauri 宿主提供窗口和系统能力，界面只能经宿主转发的通道调用后端 | active |
| Android 应用 | 移动界面、目录授权、HTTP 客户端 | Capacitor + Java 插件；活动传输由持续通知保持，持久目录授权与远端 IP 相互独立；局域网搜索用 NsdManager，扫码用 CameraX 取景、ZXing 解码 | active |
| 任务控制与传输 | 显式方向、传输进度、文件流和结果 | 两端均可发起覆盖复制；拨号方编排扫描、计划和任务，监听方发起时经控制通道交给拨号方，需拨号方开着应用并已连接（当前即电脑发起、移动端执行）；目标多出的条目默认保留，每次可选择删除 | active |
| 备份与恢复 | 写入前保存目标目录的全部文件，提供手工恢复 | 默认关闭，每个游戏保留 1–4096 份（默认 10 份）；独立于同步目录和任务比较数据；删除同样算写入，先备份 | active |

### 3.1 设备识别与地址更新

1. 下面 1–4 条以电脑作监听方、Android 作拨号方为例，两种平台担任任一角色时规则相同。Windows HTTP 服务监听 `0.0.0.0`，界面显示一个推荐 IPv4 地址、端口和稳定设备 ID；地址先取物理网卡上有默认网关的接口，再取其他有默认网关的接口，同级按默认路由 metric 排序；连接二维码最多带 8 个候选地址。服务运行期间电脑用 mDNS 广播，Android 从发现列表、扫码或手动 IP 连接并读取设备描述。
2. 建立连接后核对设备 ID，关联保存的设备记录；地址或显示名称不作为设备身份。
3. DHCP 或网络变化时旧连接失效。Android 点已保存设备的“连接”时，连保存的地址的同时在后台按设备 ID 用 DNS-SD 查找 5 秒；保存的地址连上就停止查找，连不上或上面是另一台设备时，查到了就连接并更新地址；附近已搜到这台设备且地址变了时直接连搜到的地址。没查到时按连接失败提示，由用户手动改址或扫码；原地址不回应时约 5 秒得出结果。项目与目录映射按设备 ID 保存，改址后保留；新地址返回不同设备 ID 时不替换已保存的设备。
4. 查找只在点连接时进行，已连着的控制通道断开后回到未连接。异常断开后 Android 会话保留 10 秒等对方恢复，这期间点连接时，没有进行中的任务就先释放本机会话再连；配对码不在范围内，定位设备不依赖公网服务。
5. 发现和二维码协议与设备页按对称角色设计：广播服务和显示二维码的是监听方，搜索和扫码的是拨号方，不按平台区分；唯一例外是扫码只在移动端提供，桌面端作为拨号方时用发现列表和手动 IP。一台设备同一时刻只有一条连接，作为监听方被连着或作为拨号方连着别人；拨号方连着别人时本机监听服务拒绝新的连接（`busy`）。Android 开着本机服务时由前台服务和常驻通知保持监听。

### 3.2 本次同步流程

1. 两端已连接后，用户可在任一端选择项目和方向（从监听方到拨号方或反过来，界面以“本机”和对方设备名显示两端）。目标有多出的条目时可选择保留或删除，默认保留。
2. 重新扫描当前源目录和目标目录，生成本次临时清单；按相对路径、类型、大小和修改日期比较，大小相同且修改日期相差不超过 2 秒的文件算相同（兼容 FAT 和 exFAT 的日期精度）。
3. 源端独有条目复制；同路径的文件不同时按所选方向覆盖；相同的文件跳过；目标端独有条目由本次的保留开关决定。
4. 没有“首次同步”分支，没有依据日期选择权威端或双向修改冲突合并的逻辑。选择删除时先完成全部写入再删除，写入失败时一项都不删。
5. 展示本次新增、覆盖、保留和删除计划；源目录不可读、目录授权失效与真实空目录必须区分。
6. 任务分备份、传输、写入三步。接收端登记任务后立即开始备份：备份开启且计划有写入时，在目标端独立备份区保存目标目录的全部文件，包括未变化和目标独有文件；每个游戏保留 1–4096 份（默认 10 份），用于手工恢复。备份与传输同时进行：发送端把待传文件边读边打包为 tar.gz，经分块 HTTP 发送，接收端边收边解包到私有目录。备份完成且内容收齐后，接收端重新核对目标目录，再逐文件写入并显示逐文件结果。写入按文件完成，部分成功会保留并列出未完成项。内容传输失败时一项都不写；备份或核对失败时停止接收。
7. 断线重连后重新扫描；已成功写入的文件成为当前文件状态，不依赖旧任务清单、历史数量或旧方向继续判定。临时比较数据在任务结束后丢弃。
8. 备份默认关闭、可开启，仅用于手工恢复，不参与下次比较；写坏或写入中断时重新传输。传输期间发现文件变化时重扫或报告失败。Android 不判断前后台，仅传输保活；中断后重新读取当前目录，界面重建时查询同一原生传输任务。写入目标前在私有目录落盘写入标记，结束时删除；启动时发现上个进程留下的标记就提示一次文件可能不完整。

### 3.3 预览数据与展示

| 字段 | 含义和展示 |
| --- | --- |
| 相对路径、条目类型 | 两端分别读取，可展开子目录；明确区分文件和文件夹 |
| 文件大小 | 字节数，可格式化为 KiB / MiB；未知与不存在分开表示 |
| 文件夹大小 | 不递归计算，不用文件夹自身存储占用冒充内容大小；建议显示“—” |
| 修改日期 | 文件或文件夹条目自身返回的时间；以时间戳传输并按查看端时区显示，未知则标明 |
| 内容比较 | 扫描完成即由大小和修改日期标为相同或不同，修改日期相差不超过 2 秒算相同 |
| 扫描状态 | 正在读取、读取成功、未知属性、权限失效、读取失败、条目不存在分别展示 |

列目录只查当前层，展开时再查下一层。条目用平台给的不透明 `entryId` 定位，不用显示名称拼路径；文件大小未知用 null，空文件用 0。提供者能力分支持、不支持和未知，以实际操作结果为准。

两端都用共用的并排文件列，列内布局按列宽切换。预览数据来自本次读取，执行前还会重新检查。目录修改时间只描述目录本身，不汇总后代文件。Android 能否保留写入文件的原修改日期由提供者能力决定，同步后展示目标端实际属性。

## 4. 关键决策

| 事项 | 当前结论 | 状态 |
| --- | --- | --- |
| 明文 HTTP、手选方向、无历史基线、目录不递归计算大小 | 产品决定；具体约束见[产品需求](../requirements/product.md) | accepted |
| React 双端技术栈 | React + TypeScript + Vite，桌面端 Tauri + antd，Android Capacitor + antd-mobile | accepted |
| 桌面端宿主和存储目录 | Tauri 宿主和 Node sidecar，存储按 Roaming（界面偏好）、Local（数据、备份库）、缓存分开，支持 `portable_data` 便携模式和自定义备份库，见 [ADR-0005](../decisions/ADR-0005-tauri-sidecar-and-storage-layout.md) | accepted |
| 稳定 ID、地址和目录映射解耦 | 改址后保留目录配置；连保存的地址时同时按设备 ID 查找 5 秒（Q-016），原地址连不上又没查到时再手动改址或扫码 | accepted |
| 首次连接入口 | 发现列表、扫码和手动 IP，三个入口都核对设备 ID | accepted |
| 连接与传输角色 | 监听方提供服务、拨号方编排传输，方向和两端按角色命名；一台设备同一时刻只有一条连接；见 [ADR-0004](../decisions/ADR-0004-symmetric-listener-dialer-roles.md) | accepted |
| 复制与备份 | 默认覆盖复制并保留目标多出的条目，每次可选择删除。写入前备份由发起端在传输页按次选择，默认关闭；备份库统一设置每个游戏保留 1–4096 份（默认 10 份） | accepted |
| Android 生命周期 | 不判断前后台，只保持传输和用户开着的本机服务；普通操作不处理切后台后的成败。任务由用户显式发起，自动调度不在范围内；连接可用时两端均可发起任务 | accepted |
| 文件传输格式 | 双向唯一 tar.gz，边打包边发送、边收边解包；内容收齐且备份完成后才逐项写入；见[设备接口与归档格式](transfer-protocol.md) | accepted |
