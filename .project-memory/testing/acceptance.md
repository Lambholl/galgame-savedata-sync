## 1. 支持范围与真实存档

已实测的写入环境：Windows 本机 NTFS 目录；Linux 本机 ext4 目录；Android 主存储的 SAF 目录，以及授权“所有文件访问权限”后的直接读写。SD 卡、第三方文件提供者和其他桌面端文件系统没有实测，不算已支持；提供者不满足写入约定时按 `unsupported-operation` 拒绝。复制、备份和恢复的规则见[复制、备份与恢复约定](../architecture/sync-copy.md)。

真实存档覆盖在上述范围内开放，单次限制最多 1024 个文件、单文件 256 MiB、合计 1 GiB，备份默认关闭。Android 覆盖是原地写入，写入中断会留下新旧混合的文件，重新传输即可修复，开着备份时也可以从备份恢复。写入中断后，下次打开应用提示文件可能不完整、请重新传输，有备份时可直接查看备份；关闭备份的传输不另加警告：备份是附加功能，本应用不提供这一级的完整性保证。真实存档不用于故障注入。

## 2. 规模与资源基线

满额 1 GiB 双向传输（TC-036）：四个 256 MiB 随机文件经局域网往返，外部 SHA-256 全部一致，源大小和修改日期保持，任务缓存清理完成。电脑到手机约 88 秒，手机到电脑约 215 秒，慢在手机到电脑时电脑逐文件发布。采样峰值：电脑主进程 RSS 约 171 MiB，所有应用进程工作集合计约 430 MiB（含共享页重复计数）；手机主进程 RSS 约 232 MiB，独立 WebView 渲染进程不计入。电脑把可用容量注入为零时，目标和私有缓存都在开始前返回 `insufficient-space`。这组数据测于边打包边发送、备份与传输并行之前的实现，当前实现没有重测这组数据；当前实现上，电脑到 Android、电脑之间的 1 GiB 传输都已通过；电脑之间走本机回环，采样峰值为主进程工作集约 195 MiB、单个实例全部进程合计约 535 MiB。

复制、备份和恢复的空间峰值只测了 191 MiB 的文件：手机作目标覆盖时用 575 MiB，恢复再多 193 MiB；电脑作目标 762 MiB，恢复 382 MiB，作来源 382 MiB。满额 1 GiB 的备份和恢复峰值没测。

## 3. 功能验收状态

| 功能 | 验收条件 | 测试方式 | 状态 |
| --- | --- | --- | --- |
| 平台与目录授权 | Windows、Linux（X11 和 Wayland 会话）与 Android 11 及较新系统可运行，授权目录可读写；应用重启后恢复有效目录授权 | 真机与桌面集成验证 | passed |
| 明文 HTTP | 在无 TLS、证书和加密配置的局域网完成连接、控制与文件往返 | 网络与集成验证 | passed |
| 方向选择 | 明确选择电脑 → Android 或 Android → 电脑后，内容按该方向应用；修改日期较新的一端不影响方向 | 双向场景验证 | passed |
| 当前状态独立 | 两端当前文件、方向和模式相同时，先前未同步、不同方向同步或不同同步次数均得到相同计划；不存在历史基线依赖 | 实际场景与集成验证 | passed |
| 配置保持 | 重启应用或手动更新设备 IP，项目与目录映射仍存在；地址属于另一设备时提示重新关联 | 场景验证 | passed |
| 发现、扫码与 DHCP 重连 | 首次连接提供发现列表、扫码和手动 IP，都核对设备 ID；更改 Windows 地址后通过 mDNS/DNS-SD 重新发现并连接，发现不可用时通过扫码或手动改址完成，原目录配置保留 | 真机验证：TC-043～TC-047。发现列表、扫码、电脑换端口和换 IP 后自动重连、组播不可用时手动改址或扫码、多网卡电脑扫码都通过，原目录配置保留 | passed |
| 文件与文件夹预览 | 两端条目可浏览、展开；文件显示实际大小和修改日期，文件夹显示可获得的自身日期；未知属性与不存在明确区分 | 界面与提供者验证 | passed |
| 不统计文件夹大小 | 打开、展开、刷新预览不为文件夹大小做递归汇总；文件夹大小显示“—”等非汇总值。同步所需递归枚举仍正常工作 | 扫描适配器调用验证已通过；真实存档大目录（503 个文件）两端预览的文件夹大小都显示“—” | passed |
| 当前内容比较 | 同路径同大小但内容不同的文件标为不同；日期不同但内容相同可跳过，日期不决定权威端 | 针对性集成验证 | passed |
| 复制与删除规则 | 默认保留目标多出的条目；切到“删除”时计划页预览删除项，先写入后删除，完成后目标与来源一致；写入失败时一项都不删；来源为空时再确认一次；不可读源返回读取失败，空目录单独表示 | M-002 验收覆盖复制、不可读源与空目录。删除：Windows 写入端合成目录通过（混合计划、只删除、来源为空、关闭备份、确认后目标变化、写入失败、删除时目录或文件变化）。真机合成目录通过：两端发起、两个方向的混合计划和只删除，保留模式，来源为空的确认文案，写入期间目标文件夹新增文件或要删的文件被改时不删除并报部分完成 | passed |
| 失败处理 | 断网、存储不足、授权失效、文件传输期间变化时结果明确；重连重新扫描，临时接收文件与已完成文件分开标记 | 真机与注入：断网、移动端存储不足、两端目录失效、传输期间变化、结果待确认已通过；电脑存储不足由 TC-036 的零余量探针覆盖，容量不足时在开始前返回 insufficient-space | passed |
| 备份 | 发起端在传输页按次选择，默认关闭；在目标端独立备份区按目标端备份库的份数保留（默认 10 份）；可手工恢复，备份不进入同步目录或影响同步判定 | 真机合成目录（含备份移到 `Android/data` 后）和 Windows 本机复核通过。删除前备份和从备份取回被删文件在 Windows 写入端和真机合成目录通过：清空目标后恢复，文件数量正确，电脑上的哈希逐个一致。传输页按次选择备份（两种发起方式、两个方向，开关开、关各一次）、改小份数后的轮换和旧格式设置文件的启动处理在电脑与 Android 真机上复核通过 | passed |
| 通知保持与两端操作 | Android 业务不判断前后台；仅传输验收持续通知/dataSync 保活、Activity 重连及完成/显式取消后清理；普通目录、扫描、连接和查询的后台成败不设验收要求；两端都能发起 | 两端发起、回桌面继续、通知、取消和真实 Activity 重建（开启“不保留活动”）已真机通过 | passed |
| 任意两台设备连接 | 电脑和 Android 都能作监听方或拨号方。拨号方从附近的设备、手动地址或已保存的设备连接，Android 另可扫码；附近的设备停止服务后约 10 秒内从列表消失。一台设备同一时刻只有一条连接，拨号方连着别人时本机服务返回 `busy`。监听方停服、断开时拨号方断开，改址后按设备 ID 重新找到；控制通道失去响应时拨号方转为重连，超时后断开，对方恢复后能重新连上 | 真机经局域网：电脑与 Android（各作一次监听方）、Android 与 Android；电脑与电脑用两个应用实例经真实 mDNS | passed |
| 任意两台设备传输 | 电脑与电脑、电脑与 Android（任一方作监听方）、Android 与 Android 之间两个方向都能传，两端都能发起。完成后两端内容一致，修改日期一致（经 SAF 写入的除外）；保留模式下目标多出的条目保留；开着备份时备份是写入前的内容；1 GiB 以内的传输完成，超过单次上限时不能开始 | 真机和真实存档复制件 | passed |
| 取消与对方无响应 | 任一端取消后两端结论一致（取消或部分完成），已写入的文件完整，目标没有残缺文件。对方无响应时，任务先记为结果待确认，连接转为重连后断开；作接收端的 Android 发现连接断开后停止写入，未写入的文件保持原样；重连后仍显示结果待确认，不读回对方记录的结果。Android 写入途中进程被结束时，重启后提示上次写入被中断，对方显示结果待确认 | 真机，冻结 Android 进程模拟无响应 | passed |
| Android 本机服务 | 本机服务开着时由 `connectedDevice` 前台服务和常驻通知保持监听，用户关掉服务才停止。应用在后台或 Activity 被销毁时，连接、比较和传输照常；对方发起的传输在通知栏显示写入进度，结束后通知消失，回到前台显示这次传输的详情 | 真机 | passed |
| 传输开始时两端打开详情 | 发起端进入传输详情，另一端自动打开同一任务的详情：停在别的页面时直接切换；电脑窗口最小化时只切换页面，不还原、不抢焦点；Android 在后台时回到前台即显示这次的详情 | 真机与两个电脑实例，短传输和 1 GiB 长传输 | passed |
| SAF 写入修改日期提示 | Android 作目标、没有所有文件访问权限且计划含文件写入时，Android 的计划页（Android 发起）或自动打开的传输详情页（对方发起）显示修改日期设不了的警告；有权限或计划没有文件写入时不显示 | 真机 | passed |
| Android 直接读写文件 | 授权所有文件访问权限后按路径读写：条目 ID 和扫描快照与 SAF 实现相同，覆盖写入后两端哈希一致，备份是写入前的内容。关闭权限后，选过的目录按 SAF 授权继续可用。Android 监听方的目录授权失效时，两端界面都指明是 Android 监听方的目录 | 真机 | passed |
