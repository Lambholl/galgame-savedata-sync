| Q-004 | 首版采用覆盖复制，还是同时提供会删除目标端独有条目的镜像模式？ | 结论：两种模式都提供，默认覆盖复制并保留目标独有条目；镜像模式让目标匹配源，执行前预览删除项 | 用户 | closed |
| Q-005 | 是否需要覆盖前备份，以及备份位置和保留策略？ | 结论：提供备份开关，默认开启，保留最近 3 次；备份放在目标端独立备份区，仅用于手工恢复，不参与同步判定 | 用户 | closed |
| Q-006 | 首版 Android 连接、活动传输生命周期及两端发起任务如何处理？ | 当前结论：Android 不判断前后台；普通目录、扫描、连接和查询不处理或验收切后台后的成败。仅传输由 dataSync 前台服务和持续通知保持，完成/显式取消与清理后停止；不增加自动同步或旧任务重放；两端发起的产品方向保持 | 用户 | closed |
| Q-007 | 是否为文件夹递归统计大小？ | 结论：不进行递归大小统计。文件夹自身修改日期可展示，大小建议显示“—”；同步所需的子目录枚举仍可执行 | 用户 | closed |
| Q-008 | 多小文件采用何种网络传输格式？ | 结论：双向唯一 tar.gz，按本次当前集合合批，原生 HTTP 传输，完整校验后逐项发布；没有历史基线，真实存档只读。正式设计见 docs/plans/m001-tar-gzip-protocol.md；共享数据、双端归档、Windows HTTP、原生非覆盖发布、SAF 发布及 Android HTTP/持续通知已经可用，正式 LAN、后台继续和完整平台组合已通过真机验收 | 用户 | closed |
