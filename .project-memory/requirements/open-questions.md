# 开放问题

保留问题及其结论。问题得到解答后更新“影响/结论”和状态，但不删除对应行；只有重复或错误条目可以清理，编号不得复用。

| ID | 问题 | 影响 | 负责人 | 状态 |
| --- | --- | --- | --- | --- |
| Q-001 | 是否正式选定 React + TypeScript + Vite、Windows Electron + antd、Android Capacitor + antd-mobile？ | 结论：采用该 React 双端技术栈；平台文件与发现能力按架构适配 | 维护者 | closed |
| Q-002 | 首次配对采用发现列表、扫码、配对码中的哪些入口？ | 结论：首版采用发现列表 + 手动 IP；扫码后续补充，配对码不纳入首版 | 维护者 | closed |
| Q-003 | 是否在首版加入 mDNS/DNS-SD 自动发现？ | 结论：加入 mDNS/DNS-SD 自动发现及改址重连，另提供手动 IP 入口；稳定设备 ID 与目录配置关联，地址变化不重建映射 | 维护者 | closed |
| Q-004 | 首版采用覆盖复制，还是同时提供会删除目标端独有条目的镜像模式？ | 结论：不分两种模式，传输页用一个开关选择保留或删除目标多出的条目，默认保留；删除时计划页预览删除项，完成后目标与来源一致 | 维护者 | closed |
| Q-005 | 是否需要覆盖前备份，以及备份位置和保留策略？ | 结论：提供写入前备份开关，默认开启，每个游戏保留 1–10 份（默认 3 份）；有写入时保存目标目录全部文件，放在目标端独立备份区，仅用于手工恢复，不参与同步判定 | 维护者 | closed |
| Q-006 | 首版 Android 连接、活动传输生命周期及两端发起任务如何处理？ | 当前结论：Android 不判断前后台；普通目录、扫描、连接和查询不处理或验收切后台后的成败。仅传输由 dataSync 前台服务和持续通知保持，完成/显式取消与清理后停止；不增加自动同步或旧任务重放；两端都能发起任务 | 维护者 | closed |
| Q-007 | 是否为文件夹递归统计大小？ | 结论：不进行递归大小统计。文件夹自身修改日期可展示，大小建议显示“—”；同步所需的子目录枚举仍可执行 | 维护者 | closed |
| Q-008 | 多小文件采用何种网络传输格式？ | 结论：双向唯一 tar.gz，按本次当前集合合批，原生 HTTP 传输，完整校验后逐项发布；没有历史基线。正式设计见 docs/plans/m001-tar-gzip-protocol.md | 维护者 | closed |
| Q-009 | 启动页改为设备页是否两端都改、是否每次冷启动都生效？传输详情返回的“主页”是游戏页还是设备页？其余页面的返回目标是什么？ | 结论：两端都改，每次冷启动进设备页，从后台返回留在原页。传输详情返回游戏页。其余返回目标见[实现细节](../development/implementation-notes.md)的“页面导航与返回” | 维护者 | closed |
| Q-010 | 从文件夹选择器等应用自己打开的系统界面返回时，是否也播放开屏动画？ | 结论：不播放。切换应用、回到桌面、锁屏后返回都播放，不另设最短离开时间 | 维护者 | closed |
| Q-011 | 平板是否同时支持横竖屏（手机仍锁竖屏）？大屏导航是否改为左侧导航栏？ | 结论：屏幕最短边不小于 600dp 时支持横竖屏，其余设备锁竖屏；大屏用左侧导航栏，内容限制最大宽度，游戏网格按宽度增加列数，底部弹层限宽居中。验证设备最短边约 807dp，系统为 Android 15 | 维护者 | closed |
| Q-012 | 两端备份规则是否统一：电脑端轮换是否也把不完整的备份计入份数并最先删除？清理或轮换真的失败后是否还挡新备份？ | 现状：移动端不完整的备份占份数并最先删除，失败后本次运行内挡新备份；电脑端不完整的备份不计入也不删，失败后不挡。电脑端轮换暂不改 | 维护者 | open |
