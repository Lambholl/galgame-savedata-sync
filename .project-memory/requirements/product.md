## 1. 摘要

- 核心问题：在 Windows 与 Android 设备之间手工往返复制游戏存档不便。
- 目标用户：同一局域网内在电脑和 Android 设备之间切换的使用者。
- 核心价值：将文件夹映射保存为项目，浏览两端当前文件，手动选择方向后同步。
- 当前范围：以下 active 需求及方案选择已由用户确认；基础设施、双端空壳、共享批量契约、双端目录读取、Windows 私有归档及 HTTP sender 已建立，Windows 原生非覆盖发布及 HTTP receiver 批次编排已实现；Android 归档/发布/网络、跨端编排与同步业务尚未实现。已解答问题保留在[开放问题](open-questions.md)，当前方案见[架构总览](../architecture/overview.md)。

## 2. 需求清单

| ID | 需求 | 优先级 | 状态 | 验收标准 |
| --- | --- | --- | --- | --- |
| REQ-001 | 首版支持 Windows 与 Android 10（API 29）及以上；两端在同一局域网且同时在线 | P0 | active | 安装及基本同步在约定的平台版本验证通过 |
| REQ-002 | 以同步项目统一管理游戏或文件夹，保存两端目录的对应关系 | P0 | active | 可管理多个项目，重启后仍可读取配置 |
| REQ-003 | 使用明文 HTTP 通信，不引入 TLS 或数据加密 | P0 | active | 配对、控制及文件传输均可在无证书环境通过 HTTP 完成 |
| REQ-004 | 用户手动选择电脑 → Android 或 Android → 电脑 | P0 | active | 每次操作清楚显示源端与目标端，不自动推断方向 |
| REQ-005 | 同步只取决于本次当前状态，不依赖以往是否同步、时间、方向、文件数量或大小 | P0 | active | 当前文件、所选方向和模式一致时，改变历史记录不改变本次结果 |
| REQ-006 | 不存在持久化的两端共同同步基线 | P0 | active | 不保存或读取历史清单与历史哈希作为同步判定依据；仅允许本次任务临时扫描结果 |
| REQ-007 | DHCP 地址变化后可重新连接；至少允许重新配置 IP 并保留原文件夹配置 | P0 | active | 更换地址后原项目与目录映射无需重建 |
| REQ-008 | 提供两端文件夹和文件的浏览、属性预览 | P0 | active | 可查看目录层级及各端条目，预览基于当前读取结果 |
| REQ-009 | 文件显示当前大小和修改日期；文件夹显示可获得的自身修改日期 | P0 | active | 两端属性可对照；未知值与条目不存在可以区分；日期不用于自动决定方向 |
| REQ-010 | 文件夹不递归计算或展示汇总大小 | P0 | active | 打开、刷新或同步预览均不为文件夹大小汇总而遍历后代；大小列建议显示“—” |
| REQ-011 | 采用 React + TypeScript + Vite；Windows 使用 Electron + antd，Android 使用 Capacitor + antd-mobile | P0 | active | 两端按已选技术栈构建；平台适配与共用逻辑分离 |
| REQ-012 | 首版提供设备发现列表与手动 IP 入口 | P0 | active | 能从发现列表连接，也能输入或更新 IP、端口；扫码后续补充 |
| REQ-013 | mDNS/DNS-SD 自动发现当前地址，手动 IP 兜底 | P0 | active | DHCP 改址后重新找到同一设备；发现不可用时可手动连接且目录映射保留 |
| REQ-014 | 同时提供覆盖复制与镜像同步，默认覆盖复制 | P0 | active | 覆盖复制保留目标独有条目；镜像预览删除项并让目标与源匹配 |
| REQ-015 | 提供覆盖前备份开关，默认开启，保留最近 3 次 | P0 | active | 目标端独立备份区可手工恢复；备份不进入同步目录或同步判定；保留策略可验证 |
| REQ-016 | Android 仅支持前台；前台连接时允许两端发起同步 | P0 | active | Android 前台可从任一端发起任务；不提供后台同步服务或后台传输能力 |
| REQ-017 | 检查所有项目依赖版本，避免引入已知漏洞版本，包括开发、间接依赖和 Android 构建依赖 | P0 | active | 依赖变更后执行官方 npm / OSV 审计与上游安全公告核对；已知漏洞需修复；网络或依赖解析失败不计作审计通过 |
| REQ-018 | 双向统一采用 tar.gz 作为唯一文件传输方案，按本次待传集合合批 | P0 | active | Windows 与 Android 原生层打包/解包，经 HTTP 流传输；接收端逐文件校验并反馈实际结果；格式决定不改变当前状态判定、复制模式、备份与前台边界 |

## 3. 约束

| 约束 | 影响 |
| --- | --- |
| 不依赖游戏引擎、运行器或存档格式 | 用户选择要处理的目录，工具执行通用文件操作 |
| 文件夹大小不递归统计 | 文件级大小仍可读取；为同步枚举子目录与为目录汇总大小是不同操作 |
| 已选 React 双端技术栈 | 需求与方案已确认；当前只实现基础设施和空壳，不扩展到同步业务 |
| Android 仅前台 | 后台运行、后台保活及后台传输不属于本工具范围 |
