# 项目约束

| 类型 | 约束 | 影响 | 状态 |
| --- | --- | --- | --- |
| 平台 | Windows；Android 最低 Android 11 / API 30，编译和目标 API 36 | 写在原生工程 variables.gradle；SDK 更新时保持最低版本。最低版本由所有文件访问权限决定（ADR-0003），不为更旧的系统或 WebView 写兼容代码 | active |
| 网络 | 同一局域网，两端同时在线；明文 HTTP、不加密 | 协议不要求证书；Android 需配置明文访问和目标系统所需的局域网权限 | active |
| 同步 | 手选方向；每次以两端当前状态为准 | 不从修改日期或历史推断权威端，不建立共同历史基线 | active |
| 同步期间的目录 | 同步过程中，目标目录不能被游戏或其他程序持续写入 | 工具自身的任务锁拦不住其他程序修改文件，扫描和传输检查只能发现变化；修改中途失败时的处理和产品提示还没验证 | active |
| 预览 | 文件夹不递归计算大小 | 显示文件自身大小；文件夹大小建议显示“—”，不做后代汇总 | active |
| 配置 | IP 地址不是文件夹配置的标识 | 设备关系、连接地址、项目目录映射分别保存 | active |
| 开发方式 | React + TypeScript + Vite；共用协议、数据模型、业务规则，以及与两端交互差异无关的界面渲染（ADR-0002）；平台交互、页面状态与 Hook 各端实现 | apps 下分为 mobile、desktop、shared，共用渲染走 `@savedata-sync/shared/ui`；Windows Tauri + antd；Android Capacitor，优先 antd-mobile，使用 antd 时也考虑触控；平台能力各自适配 | active |
| 连接 | 发现列表、扫码和手动 IP；mDNS/DNS-SD 自动发现；角色按监听方和拨号方区分，不按平台；扫码只在移动端提供 | 自动发现受局域网条件影响时，移动端仍可扫码，两端都可手动改址；配置不随 IP 变化丢失；三个入口都核对设备 ID | active |
| 目标多出的条目 | 默认保留，每次传输可选择删除 | 只有本次切到“删除”时才列入计划，选择不保存；来源目录为空时删除前必须再确认一次 | active |
| 备份 | 由发起端在传输计划页按次选择，默认关闭；保留份数归存放备份的设备，备份库统一设置每个游戏保留 1–4096 份（默认 10 份） | 开启且有写入时保存目标目录全部文件；放在目标端独立备份区，不参与差异判定，不作为同步源内容。备份关闭时被覆盖和删除的文件直接丢弃，界面不按危险操作提示 | active |
| 文件安全保证 | 以 SMB、FTP、SCP 这类文件传输工具为基准，不提供更多的文件安全保证；额外的检查只在不明显影响耗时时保留。后续性能优化按这条删减检查 | 写坏或写入中断时的处理是重新传输，备份只是可选的附加功能；逐文件的身份核对只查目标文档本身，不为它列目录或重新授权 | active |
| 本机文件速度 | 备份阶段、写入目标目录和从备份恢复不做多余的步骤，最终耗时是否可以接受由维护者按实测判断。参考：一层 503 个文件、97 MiB 的真实存档目录，在 Windows 上 `cp -r` 约 0.3～0.5 秒、robocopy 约 0.1 秒；Android shell `cp -r` 约 0.4 秒，经 SAF 每打开一个文件约 29 ms，所以 Android 扫描、备份和打包都同时打开 8 个文件：这个目录比较约 7～8 秒，备份约 4～6 秒；手机作为来源时打包 700 个文件、175 MiB 约 15 秒，其中 gzip 约一半。有所有文件访问权限时，系统存储提供者上的目录直接读写文件（ADR-0003），这个目录扫描降到约 2.2～2.4 秒（SAF 约 4.7～5.0 秒），列出这一层约 0.4～0.7 秒（SAF 约 0.5 秒） | 备份和写入不单独调用 fsync，交给系统落盘：系统崩溃或断电时，刚提交的备份可能不完整。复制时边写边算哈希并和扫描结果比对，不重读写好的文件；写存档目录仍先写临时文件再改名替换。不逐文件做额外的目录列举、属性查询或空间查询 | active |
| Android 生命周期 | 业务不判断前后台状态；只保持传输和本机服务 | 普通目录、扫描、连接和查询不处理切后台后的成败；传输使用 dataSync 前台服务和持续通知，保留显式取消、期限和实际错误处理。本机服务开着时由前台服务和常驻通知保持监听，应用退到后台或 Activity 销毁都不停止，用户关掉服务才停（见 Q-018、ADR-0004）。不增加自动同步、定时/开机任务或旧任务重放 | active |
| Android 文件系统 | 使用用户实际能够授权访问的目录；SAF 属性可能未知，部分操作能力由提供者决定。目录总是经系统选择器选择；有所有文件访问权限且目录属于系统存储提供者时直接读写文件，否则走 SAF，两条路返回同样的 ID 和属性 | 按提供者实际能力处理目录和日期；`Android/data`、`Android/obb` 两条路都进不去 | active |
| 兼容性 | 早期测试阶段，不为早期设计保留针对性的兼容或升级代码 | 配置、备份等落盘格式、协议字段和接口变化时直接换成新的，不读取、不转换、不迁移旧格式，不保留旧接口；读到其他版本按格式错误处理。能提升健壮性的通用处理可以保留，如版本不同时拒绝连接、文件损坏时报错、兼容不同文件系统的日期精度。公开发布后是否改变由维护者决定 | active |
| 依赖安全 | 手动命令全量检查项目直接、间接、开发及 Android 构建依赖，日常 CI 移除安全审计步骤 | 固定版本与 lockfile，命中公告应修复；手动审计无法完成时明确失败，不抑制已知漏洞 | active |
