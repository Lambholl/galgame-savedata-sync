## 3. 执行与拆分规则

- 推荐顺序为 WP-001 至 WP-008；设备可用时提前验证 WP-003 的目录能力，最后由 WP-008 汇总证据。该依赖设计不授权并行 Agent。
- 一包只承担一个主要能力边界。跨平台契约变更、提供者差异、无法独立验证或新增依赖/配置迁移使范围扩大时，先拆出新包；保留原包已完成与剩余范围，新包不重复承诺交付物。详细规则见 `docs/plans/m001-directory-http.md` 第 6 节；新 ID 从 WP-009 起分配，不回退高水位。
- 实现前读取并满足根 AGENTS.md、antd skill、项目及目标语言编码规范；apps 修改另读取子目录规则。设计授权不能当作实现或提交授权。
- 工作包完成以针对性检查、受影响工程检查及明确剩余缺口为证据；真机未测不能写成产品通过。完成、阻塞和下一步同步 INDEX、模块状态、用例和回归状态。
- 后续 M-002 至 M-004 仅保留设计中的拆分方向；进入对应里程碑时重新读取记忆并细化，不提前将整个产品当作一个工作包。
