## 1. 状态与入口

用户授权 WP-003 实现和连接设备验证，允许安装调试/测试 APK 及操作应用私有测试配置，沿用 Java。新文件写入拆至 WP-010，仅独立夹具可用于后续写入测试。

详细范围与流程位于 `docs/plans/m001-directory-http.md`；[接口契约](../architecture/api-contracts.md)与[模块设计](../architecture/modules.md)维护当前边界。共享与平台说明见 `packages/shared/README.md`、`apps/desktop/README.md`、`apps/mobile/README.md`。基础设施、共享契约及双端目录读取已完成；Java SAF 通过 API 33 合成夹具复测与旧 API 35 读取/恢复验证；两机证据不混用。新文件发布、HTTP 与同步流程未实现，本次目录适配尚未远端验证。

双向传输已确定统一采用 tar.gz，见[Q-008](../requirements/open-questions.md)。下一步先细化批量清单、路由/DTO、逐文件结果、批次限制和失败语义，再调整下列未实现包与详细计划；现有共享包的单文件传输类型需同步修订。该设计前置于 WP-004 实现，跨平台契约与双端归档能力应独立拆包，新增编号沿用高水位规则。本轮只更新方案记忆，未开始设计包或产品实现。

## 3. 执行与拆分规则

- 双端读取完成后的下一步是 tar.gz 批量契约设计与分包；完成后更新 WP-004 起的依赖。现有顺序为 WP-004、WP-009、WP-005、WP-010、WP-006、WP-007、WP-008；两端写入独立验证后再接原生 HTTP，最后由 WP-008 汇总证据。该依赖设计不授权并行 Agent。
- 一包只承担一个主要能力边界。跨平台契约变更、提供者差异、无法独立验证或新增依赖/配置迁移使范围扩大时先拆包；保留原包交接，新包不重复承诺。详细规则见 `docs/plans/m001-directory-http.md` 第 6 节；新 ID 从 WP-011 起分配，不回退高水位。
- 实现前读取并满足根 AGENTS.md、antd skill、项目及目标语言编码规范；apps 修改另读取子目录规则。设计授权不能当作实现或提交授权。
- 工作包完成以针对性检查、受影响工程检查及明确剩余缺口为证据；真机未测不能写成产品通过。完成、阻塞和下一步同步 INDEX、模块状态、用例和回归状态。
- 后续 M-002 至 M-004 仅保留设计中的拆分方向；进入对应里程碑时重新读取记忆并细化，不提前将整个产品当作一个工作包。
