| 开屏圆形遮罩与角色退出 | 第一次眨眼在 200 ms 结束时开始扩大圆形遮罩，到 700 ms 覆盖窗口，头像的屏幕位置和比例保持不变。第二次眨眼在 550 ms 结束时背景开始淡出，遮罩结束后停 250 ms，角色在 950–1350 ms 保持不透明向下滑出，头顶越过窗口底边时背景正好全透明。遮罩和下滑都在各自前 30% 的时间里从零匀加速，之后匀速，位置与速度连续。遮罩开始扩大前只绘制头像帧；遮罩扩大后按实际图片宽高比和与头像相同的宽度、像素网格绘制完整立绘（运行时只生成一份身体位图），再裁剪叠加当前帧的眼睛局部（648 px 逻辑坐标 x 218–428、y 313–395，与素材分辨率无关，含眨眼差异和缩放滤波余量） | Android LaunchAnimation.java |

| Android 眨眼开屏 | 设置页外观分组的“开屏动画”开关决定是否播放，默认打开，保存在 `app-preferences` 的 `launchAnimation`（布尔值，没有或类型不对时为打开），改动下次冷启动或从后台返回时生效。关闭时 LaunchAnimation 按不播放创建：冷启动的系统静态头像照常显示（Android 12+ 去不掉），由覆盖层接住，等网页首屏就绪后直接移除，不眨眼、不滑出；从后台返回和 Activity 重建不显示覆盖层。下面描述的是开关打开时的行为。系统启动图为 splash_open.webp。应用首帧前先准备原生头像覆盖层；系统开屏退出时立即移除系统副本，等网页首屏或启动错误提示通过 LaunchAnimation.ready 和 WebView 可绘制回调后，按 open、slight、half、near、closed、near、half、slight、open 的顺序播放两次眨眼（splash_*.webp），每帧 25 ms，两次之间停在睁眼帧 150 ms，整段 550 ms。后续遮罩、背景和角色退出见“开屏圆形遮罩与角色退出”。转后台时清理覆盖层，系统关闭动画效果时跳过播放；点按可跳过整个动画，等待超过 5 秒时超时移除覆盖层。从后台返回（onRestart）和 Activity 重建都新建 LaunchAnimation 再播放一次：系统开屏不一定出现，所以不等退出回调，也不等系统的窗口切换动画结束，第一次绘制时就开始眨眼，平板上约 100 ms；网页首屏没就绪时继续等 ready。离开后很快返回时 Activity 还没收到 onStop，只走 onPause 和 onResume，不播放；平板上间隔不超过 0.4 秒不播放，0.7 秒起播放。应用自己打开文件夹选择器时，MainActivity.startActivityForResult 留下标记，从选择器返回不播放；选择器期间 Activity 被重建时标记丢失，会播放。系统从后台恢复窗口时会先显示任务快照，开关打开时 Android 13+ 用 setRecentsScreenshotEnabled(false) 关闭，最近任务里因此不保存页面缩略图；开关关闭时恢复截图，切换开关后由 MainActivity.applyLaunchAnimationSetting 立即更新；Android 11–12 没有这个接口，快照不受影响。WebView 低于 140 时 Capacitor 给 DecorView 添加系统栏边距，系统开屏头像副本会随之下移，所以开屏期间先把同一份边距移到 android.R.id.content，布局未完成时跳过该帧，退出后再恢复。五张头像帧均为 444 × 444 像素的无损 WebP | mobile MainActivity、LaunchAnimation.java、LaunchAnimationPlugin.java、AppPreferencesPlugin.java、platform/launch-animation.ts、app/launch-animation-setting.ts、main.tsx、styles.xml、drawable-nodpi/splash_*.webp |

| 游戏入口与操作面板 | 移动端的添加、导入入口在页头。双端共用游戏卡片（shared GameCard，两端各有一层平台包装），使用 3:4 占位封面，下方单行显示并省略名称与关联摘要；移动端每行三张。悬停或按下时只给封面着色，卡片按钮本身透明、无边框、无阴影，文字背景不变。桌面端可用左键、右键和键盘打开游戏菜单。列表任务入口使用 56px 高的紧凑横条，原生 Progress steps 按备份、传输、写入三等分，已完成为绿、当前为蓝、已知错误为红、后续为灰；旁边显示当前阶段及该阶段百分比，当前段按此百分比局部填充（50% 为半段），不按三等分估算总耗时；标题占用状态文字和箭头之外的全部可用宽度，超长再省略。详情使用带编号的标准 Steps，阶段名放在下方，并显示当前阶段的 percent；出错时保留步骤条并标红已知阶段，阶段未知时显示“没有记录失败发生在哪一步”，计数未知时圆形 Progress 显示加载状态。技术详情移动端点击切换，长按复制全部后保持展开，桌面端在内容右上角复制。长路线及较长的技术文字可以换行。顶部保留目录与关联摘要；四个次级按钮只显示图标与名称，高度从 56px 起；移除游戏保留本机文件，删除这个游戏的备份，两端任务条不再显示它已结束的任务。任务详情的“重新扫描”沿用那次传输的方向。游戏操作和取消按钮都使用常规 Button。桌面端按需读取 copyState，发送完成后显示“已发送”；游戏入口只筛选本项目的记录，没有记录时，空态显示游戏名。各端分别处理平台弹层、导航、复制提示和手势 | shared/ui games/task、双端 App/GamesPage/任务页、四语言 |
| 游戏设置与文件浏览 | 双端共用 TransferComparison：每列按自身宽度切换，400px 以上为表格三列（名称 / 大小 / 修改时间）且名称一行，更窄时名称最多两行、下方一行小字写修改时间与大小，这一行不折行，时间完整显示，列太窄时省略大小的末尾；过长名称省略并悬停显示全名。两端都是文件且内容不同时，修改日期比另一端晚 `SYNC_MODIFIED_TOLERANCE_MS` 以上的一端（`CompareItem.isNewer`）日期用覆盖色，不加粗、不加文字，只用于显示，不影响方向和计划；文件夹、只在一端有的文件和日期未知的文件不标。Android 经 SAF 写入时设不了修改日期，刚写入的文件会显示为较新。文件夹内有差异时整行与内容不同的文件同样着琥珀色。方向条左边来源、右边目标，中间为主色圆形 SwapOutlined 按钮，点击交换两端，两列按端保持 key，交换后各自的文件夹不变；设备图标按整体宽度 560px 显示。比较进度为 waiting / scanning / ready / cancelled / failed / unavailable，等待、扫描和取消的说明写在摘要行（TransferStatus 是内部组件），两列只显示加载或空白；failed 和 unavailable（目录失效、对端离线等）时摘要行换成红色 Notice 提示条，写明原因，右侧“重试”按钮重新扫描，不另显示刷新按钮；等待与扫描两端统一写“正在比较两端”，不写设备名，扫描中可取消（onCancel）。比较完成后摘要行用彩色胶囊写差异数：~N 内容不同（琥珀）、+N 只在来源有（绿，文件行同色并带绿色状态点）、−N 只在目标有（蓝，保留）；标签、文件行底色与图标状态点同色，删除目标多出的文件时用红色；悬停和读屏给出完整说明。SnapshotComparison.onlyFiles 按端分开。两列各自滚动、列头固定；翻转方向保留所在文件夹与筛选，重新扫描后截到仍存在的那一层，切换设备才重置；移动端打开计划时只隐藏比较区，返回后状态不变。摘要行分两组：左边差异数（标签间距 3px），右边是取消、备份、保留/删除、差异筛选和刷新按钮（间距 6px）；窄屏放不下时右组整组换到下一行并靠右。筛选按钮为“差异”（DiffOutlined），刷新只有图标；列表时间与大小字号窄列 10.5px、宽列 11px。窄列比宽列紧凑：行内左右边距 6px（宽列 10px），图标 26px（宽列 30px），图标与文字间距 6px（宽列 8px），时间与大小间距 5px；两列间距在比较区宽 560px 以下为 6px，以上为 8px。窄列的时间与大小不指定等宽数字，用系统字体默认的数字；宽列右对齐的两格用等宽数字（`tabular-nums`）。系统字体默认是比例数字时，按浏览器测得的宽度推算，393px 宽的手机上任意大小都能和时间排在同一行；默认是等宽数字的字体（如 Windows 的界面字体）不受这项改动影响。文件列、计划详情与任务列表的时间统一为本地时区 yy-MM-dd HH:mm（formatShortDateTime，各语言相同）。操作按钮只有右下角悬浮的胶囊主按钮：传输页“下一步”，计划页“开始传输”；移动端为 FloatingAction，文件列末尾留出 --ss-pane-end-space，计划页正文末尾留出按钮高度；电脑计划抽屉底部只有靠右的开始按钮，无分隔线。“开始前请先退出游戏”在计划摘要的说明行。按钮统一为胶囊（antd Button 组件 token、antd-mobile --border-radius），移动端按钮文字不换行；双端按钮文字用 text-box: trim-both cap alphabetic 居中，因为界面字体上方留白较多，不裁时比图标低 0.5–1px | shared/ui transfer（TransferComparison、TransferStatus、CSS）、双端传输页与 Shell、mobile FloatingAction/mobile.css、desktop.css、四语言 |

| 桌面端推荐 IPv4 地址 | 桌面端服务监听 `0.0.0.0`，服务快照的 ipv4Addresses 最多 8 项，第一项是推荐地址。本机地址取自 `os.networkInterfaces()` 的非回环 IPv4。Windows 上并行运行四个隐藏的系统命令，全部按 IP 对应，不解析网卡名和本地化标签：`route print -4` 只读活动路由表每行的目标、掩码、接口地址和 metric，得到默认路由 metric 和本机主机路由 metric；`reg query` 读网卡设备类键的 NetCfgInstanceId 和 Characteristics（NCF_PHYSICAL 且不含 NCF_VIRTUAL 为物理网卡），再读 `Tcpip\Parameters\Interfaces\{GUID}` 的 IPAddress 和 DhcpIPAddress，只取 GUID 子键本身，按无线网络分开的子键里是以前网络的地址。用含多种虚拟网卡（虚拟机、VPN、Wi-Fi Direct）的注册表样本核对，这些网卡都判为非物理；Hyper-V 的 vEthernet 不在设备类键下，同样按非物理处理。注册表读取失败只记警告并按没有物理网卡处理，路由表读取失败时整次查询失败。实测一次查询约 130 ms；同样的信息用 PowerShell（Get-NetAdapter、Get-NetRoute 等）查询，同一台电脑上每次 3.2–3.8 秒，因此不用。Linux 上不运行外部命令：读 `/proc/net/route`（主路由表）得到每块网卡上带 RTF_UP 的默认路由和全部路由的最小 metric，没有默认路由的网卡用后者；`/sys/class/net/<网卡>/device` 存在即为物理网卡，网桥、veth、Docker 和 TUN 都没有这个链接。路由表和 sysfs 按网卡名对应，`os.networkInterfaces()` 报出的带标签附加地址（如 `eth0:1`）取冒号前的网卡名。sysfs 读不到时按非物理处理，路由表读取失败时整次查询失败。服务每次启动时清空缓存，快照不等待查询，读到之前 ipv4Addresses 为 null，界面每 250 ms 重读一次；读到后缓存 30 秒，过期时快照返回缓存并在后台刷新；同一时间只有一次查询，失败时记录错误并缓存空数组，30 秒后重试。局域网广播由 ciao 按网卡分别宣告该网卡自己的地址，不经过这里的选择 | desktop main/recommended-address.ts、service-ipc.ts、bridge/service-bridge.ts；renderer app/DesktopApp.tsx；shared ui/service/ServiceHero.tsx |
