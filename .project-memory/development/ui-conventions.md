## 1. 设计变量与样式

- 颜色、圆角和字体的取值只写在 `apps/shared/src/preferences/design-tokens.ts`（`PALETTES`、`RADII`、`FONTS`）。shared/ui 的 `designTheme(theme, platform)` 由它生成两端 antd ConfigProvider 主题，两端组件密度差异也集中在这里；`installDesignTokens()` 在应用入口把它写成 `--ss-*` 变量；电脑原生窗口背景读 `PALETTES`。
- 样式表只引用 `--ss-*`；antd-mobile 的 `--adm-*` 在 `mobile.css` 开头统一映射到 `--ss-*`。组件和样式表不写颜色、圆角、字体的字面值，也不用 `style` 写外观（antd-mobile 的 `--z-index` 等组件参数和布局尺寸除外）。
- 圆角档位：xs 6 小图标底；sm 10 输入框与分段控件；md 14 分组容器、卡片、文件列和大图标底；lg 22 弹层；pill 按钮与标签；圆形用 50%。
- 按钮文字不换行，放不下时改短文字或调整按钮，不靠样式折行；按钮文字用 text-box 按大写字母高度裁边后居中。
- 差异颜色两端统一：新建绿、覆盖琥珀、只在目标且保留为蓝、删除为红，标签与文件行同色。

## 2. 组件选用

- 优先复用 antd 的展示组件。列表里的紧凑进度用 Progress steps，按备份、传输、写入三段等分（计划没开备份时只有传输、写入两段）；详情用带编号的 Steps，阶段名放在下方，并显示当前阶段的 percent；圆形进度用 Progress；操作用 Button。三段表示流程位置，当前段按本阶段计数局部填充（50% 为半段），不按三等分估算总耗时。
- 移动端优先用 antd-mobile，按实际需要用 antd；弹层等平台交互沿用 antd-mobile。
- 外观相同的界面直接复用：文件列表用 FilePane，计划确认用电脑 PlanDrawer、移动端 PlanConfirm。恢复等流程打开新页面，不在原页面里切换内容。
- 取消传输用外形和点击范围都清楚的普通按钮。

## 3. 移动端尺寸

- 普通按钮 45 CSS px 起、整行主操作 50px 起；图标点击区 36px 起，选项行约 44–52px；游戏菜单的主操作和次级操作是同一种按钮，56px 起，文字 15px。
- 标题 18px，常用文字和按钮 14px，辅助文字 12px。
- 长文字换行后可以增长高度（按钮除外），常规字号和窄屏下保持可读、可点按。

## 4. 反馈与可展开内容

- 不放“详情”这类折叠开关，也不用文字链接式按钮（移动端上没有点按反馈）：入口做成整行可点的行（图标、文字、右箭头），行内操作用小胶囊 Button。
- 错误只显示本地化说明，原始消息和错误码在电脑上悬停可见，任务详情里写进技术详情。
- 提示消息都走 `useAppMessage`：每条用新 key，需要互相替换的提示用同一个 slot。页面的失败信息用 Message 提示一次（各端 `app/failure-message.ts` 的 `useFailureMessage`，同一失败连续出现只提示一次），不放红色横幅；读不到内容时正文留带“重试”的空状态；传输结束两端各用 Message 提示一次结果。任务结论、失败文件原因和比较状态栏属于记录，留在页面上；比较失败或无法比较（目录失效、对端离线等）时，比较区的摘要行换成红色 `Notice` 提示条，带“重试”按钮。`Notice` 的 error 色调用于挡住操作的问题，warning 色调只用于不挡操作的提醒。
- 可展开的内容统一用 shared/ui 的 Expand 与 ExpandChevron：朝下箭头展开后转 180°，高度平滑过渡。
- 不能点的行不加悬停和按下反馈；antd 的 Listy 默认给每行加悬停底色，不用于这类列表。
- 自定义的按钮、可点的行与卡片加 `ss-pressable`，交互时只叠加渐显的低透明前景色，不直接改背景色。移动端所有按钮只在按下时显示遮罩；桌面端悬停和按下的取值与 antd 文字按钮相同，取值见[实现细节](implementation-notes.md)。
