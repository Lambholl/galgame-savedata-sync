# 测试规范

| 主题 | 规则 | 示例 |
| --- | --- | --- |
| 文件命名 | 待补充 | 待补充 |
| 用例命名 | 待补充 | 待补充 |
| Mock 规则 | 待补充 | 待补充 |
| 新增或扩写自动化测试 | 默认禁止；只有用户在当前任务明确要求时才新增或扩写，不把一般实现请求推断为测试代码授权 | 不为让测试通过而扩展覆盖范围 |
| 已有自动化测试 | 可运行现有最小相关测试；移除已不符合当前需求的旧断言或用例 | 不把维护旧用例当作增加新场景的理由 |
| 功能验证 | 优先采用 lint、编译、ADB 实际操作和截图 | 实际传输仍通过局域网 HTTP，ADB 不代替数据通道 |
| 高风险回归 | 确有必要增加测试时，必须先向用户说明原因和预计测试代码规模，并遵守当前任务明确授权 | 不直接补测试或扩大覆盖 |
| 验证频率 | 按风险和工作包边界设置检查点；低风险批量推进后统一验证，高风险关键点后立即验证 | fast / standard / cautious |
