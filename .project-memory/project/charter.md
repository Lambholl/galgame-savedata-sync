## 1. 摘要

- 项目目标：在 Windows 电脑与 Android 设备之间，通过局域网手动选择方向同步文件夹，减少游玩 galgame 时手工复制存档的操作。
- 目标用户：在电脑与 Android 设备之间切换、需要管理多个游戏或文件夹的使用者。
- 当前阶段：M-001 已完成，双端目录/归档/发布/HTTP、通知保持、独立界面、目标真机组合及满额 1 GiB 双向资源验收通过。M-002 的复制约定、共享比较、固定项目映射及双端当前扫描/独立备份/原生受保护写入与恢复已完成，规则统一位于仓库根目录的 `docs/plans/m002-sync-copy.md`；下一包 WP-025 Android → Windows 复制编排。用户已取消 M-002 的 Android 10 实测。完整同步流程还没实现。实现见[实现细节](../development/implementation-notes.md)，M-001 结果见仓库根目录的 `docs/validation/m001-resources.md`。
- 成功标准：见[验收标准](../testing/acceptance.md)。
- 当前授权：M-002 按 WP-016 至 WP-029 的顺序开展设计、实现、配置与验证，并在每个子包完成后暂存对应成果、创建中文本地提交；同步受影响记忆。推送及其他 Git 历史操作未授权。默认不新增或扩写自动化测试。验证写入限明确选定的独立合成目标，真实存档覆盖在备份/恢复和受保护写入验收完成后按支持范围开放。

## 2. 项目目标

| 目标 | 衡量方式 | 状态 |
| --- | --- | --- |
| 两端统一管理同步项目 | 每个项目关联两端目录，支持浏览与手动选择传输方向 | active |
| 本次同步与历史无关 | 相同当前目录、方向和模式得到相同的同步计划 | active |
| 地址变化不丢配置 | DHCP 改址后可重新连接，至少可手动更新 IP 并保留文件夹配置 | active |
| 优先快速开发 | 在技术选型时优先考虑双端开发效率与逻辑复用 | active |

## 3. 成功标准

| 标准 | 验收方式 |
| --- | --- |
| 文件夹与文件可以在两端预览 | 展示目录层级、文件大小和可获得的修改日期；文件夹不递归统计大小 |
| 按明确方向传输 | 支持电脑 → Android 和 Android → 电脑，覆盖行为服从本次所选方向 |
| 配置和连接地址解耦 | 更换 IP 后原项目和目录映射仍存在 |

## 4. 非目标

| 非目标 | 原因 |
| --- | --- |
| 游戏引擎识别或存档格式转换 | 工具仅处理文件夹与文件，不解析存档语义 |
| 从历史推断方向或新旧 | 用户明确要求手选方向、只依赖当前状态 |
| TLS 和数据加密 | 当前产品假设运行于局域网，用户明确选用明文 HTTP |
| Android 后台自动同步与定时保活 | 已发起的活动传输通过持续通知/前台服务保持；没有自动调度、开机启动或旧任务重放 |
