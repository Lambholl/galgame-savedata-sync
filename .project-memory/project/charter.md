## 1. 摘要

- 项目目标：在 Windows 电脑与 Android 设备之间，通过局域网手动选择方向同步文件夹，减少游玩 galgame 时手工复制存档的操作。
- 目标用户：在电脑与 Android 设备之间切换、需要管理多个游戏或文件夹的使用者。
- 当前阶段：基础设施、双端空壳、共享契约及双端目录读取适配已建立；Java SAF 已分别在 API 33 合成夹具和旧 API 35 真实目录验证读取、选择/取消及重启授权/身份恢复，证据边界见回归状态；新文件发布、HTTP 和同步流程尚未实现。实现见[实现细节](../development/implementation-notes.md)，只读真实目录与工程验证见[回归状态](../testing/regression-notes.md)。
- 成功标准：见[验收标准](../testing/acceptance.md)。
- 当前授权：用户明确要求提交本次变更，并进一步确认包含全部当前改动：Android SAF 读取、独立双向 LAN/SAF 写入基准、tar.gz 唯一方案及配套工程/文档/记忆；允许为本次提交暂存相关文件，创建一次中文本地提交，成功后该授权耗尽，不包含推送、amend 或后续提交。此前测试数据、服务与本轮写授权已清理。用户接受 Java，沿用现有原生工具链；换机不复用新设备不存在的旧目录。真实存档禁止写入、修改和删除，root 不替代系统授权。正式批量契约、归档适配与新文件写入留后续独立设计/实现包，本轮不新增产品能力或设备写入；实际路径/原始哈希不保存到记忆。

## 2. 项目目标

| 目标 | 衡量方式 | 状态 |
| --- | --- | --- |
| 两端统一管理同步项目 | 每个项目关联两端目录，支持浏览与手动选择传输方向 | active |
| 本次同步与历史无关 | 相同当前目录、方向和模式得到相同的同步计划 | active |
| 地址变化不丢配置 | DHCP 改址后可重新连接，至少可手动更新 IP 并保留文件夹配置 | active |
| 优先快速开发 | 在技术选型时优先考虑双端开发效率与逻辑复用 | active |

## 3. 成功标准

| 标准 | 验收方式 |
| --- | --- |
| 文件夹与文件可以在两端预览 | 展示目录层级、文件大小和可获得的修改日期；文件夹不递归统计大小 |
| 按明确方向传输 | 支持电脑 → Android 和 Android → 电脑，覆盖行为服从本次所选方向 |
| 配置和连接地址解耦 | 更换 IP 后原项目和目录映射仍存在 |

## 4. 非目标

| 非目标 | 原因 |
| --- | --- |
| 游戏引擎识别或存档格式转换 | 工具仅处理文件夹与文件，不解析存档语义 |
| 从历史推断方向或新旧 | 用户明确要求手选方向、只依赖当前状态 |
| TLS 和数据加密 | 当前产品假设运行于局域网，用户明确选用明文 HTTP |
| Android 后台运行和后台传输 | 用户明确仅支持前台，不考虑后台情况 |
