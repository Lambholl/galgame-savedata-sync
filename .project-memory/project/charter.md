## 1. 摘要

- 项目目标：在 Windows 电脑与 Android 设备之间，通过局域网手动选择方向同步文件夹，减少游玩 galgame 时手工复制存档的操作。
- 目标用户：在电脑与 Android 设备之间切换、需要管理多个游戏或文件夹的使用者。
- 当前阶段：基础设施、双端空壳、v1 批量共享契约、双端目录读取与 Windows 私有归档已实现；Java SAF 在 API 33 合成夹具和 API 35 真实目录分别验证读取与授权恢复。Windows HTTP sender/receiver、会话注册与批次非覆盖发布已实现；Java 私有归档与 SAF 单文件发布已实现；Android HTTP、任务编排及持续通知保持传输已实现；最终界面和同步流程尚未实现。实现见[实现细节](../development/implementation-notes.md)，验证边界见[回归状态](../testing/regression-notes.md)。
- 成功标准：见[验收标准](../testing/acceptance.md)。
- 当前授权：本轮 WP-006 原生 HTTP 与持续通知保持传输已完成实际设备/LAN 验证，用户授权说明/记忆同步及完成后中文本地 commit；最新测试策略默认不新增或扩写自动化测试。仅精确独立合成目标获 WRITE，真实存档只读；下一建议 WP-007 最小界面，不自动启动或推送。

## 2. 项目目标

| 目标 | 衡量方式 | 状态 |
| --- | --- | --- |
| 两端统一管理同步项目 | 每个项目关联两端目录，支持浏览与手动选择传输方向 | active |
| 本次同步与历史无关 | 相同当前目录、方向和模式得到相同的同步计划 | active |
| 地址变化不丢配置 | DHCP 改址后可重新连接，至少可手动更新 IP 并保留文件夹配置 | active |
| 优先快速开发 | 在技术选型时优先考虑双端开发效率与逻辑复用 | active |

## 3. 成功标准

| 标准 | 验收方式 |
| --- | --- |
| 文件夹与文件可以在两端预览 | 展示目录层级、文件大小和可获得的修改日期；文件夹不递归统计大小 |
| 按明确方向传输 | 支持电脑 → Android 和 Android → 电脑，覆盖行为服从本次所选方向 |
| 配置和连接地址解耦 | 更换 IP 后原项目和目录映射仍存在 |

## 4. 非目标

| 非目标 | 原因 |
| --- | --- |
| 游戏引擎识别或存档格式转换 | 工具仅处理文件夹与文件，不解析存档语义 |
| 从历史推断方向或新旧 | 用户明确要求手选方向、只依赖当前状态 |
| TLS 和数据加密 | 当前产品假设运行于局域网，用户明确选用明文 HTTP |
| Android 后台自动同步与定时保活 | 已发起的活动传输通过持续通知/前台服务保持；不增加自动调度、开机启动或旧任务重放 |
