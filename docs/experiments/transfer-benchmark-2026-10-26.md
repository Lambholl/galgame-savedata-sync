## 结论

批量传输在三个样本的两个方向均优于串行保活逐文件基线。gzip 1 在高可压缩样本 C 上进一步获益，样本 B 的 tar 与 gzip 1 接近，压缩并不总是更快。xz 未测。

## 测量方法

- 真正的同一局域网 HTTP/1.1；服务只绑定电脑 LAN 地址，校验手机 Wi-Fi 对端，使用临时随机路径和已登记文件，不提供任意文件访问。没有 adb reverse/forward。
- ADB 只负责安装、将只读样本副本准备到全新的测试目录、启动仪器测试及清理；这些准备步骤不计入传输时间，不用 USB 复制当作网络速度。
- 逐文件方式串行处理，同一进程复用 HTTP 连接；服务端逐组核对数据请求数与 TCP 连接数，所有方式均为每组一条连接。服务端启用 TCP_NODELAY，避免人为引入小包延迟。
- 电脑→手机：控制请求准备本轮归档并单独计时；手机先私有暂存并核对内容，再通过 ContentResolver/DocumentsContract 为每项新建文件、写入、关闭流并回读核对 SHA-256 和实际 EOF。批量方式先完整接收并校验归档，再解包写 SAF。
- 手机→电脑：从 SAF URI 读取。逐文件直接上传，归档方式在手机私有缓存打包（可选 gzip 1）后上传；电脑在独立临时目录按原文件名接收/解包并实际回读校验后才回复成功。
- 总时间为不重叠的发送端打包时间加数据阶段时间；使用单调时钟。控制、一次目录枚举/清单准备、授权 UI 及删除基准输出目录不计时。归档私有缓存的最后删除属于测量后清理。
- 缓冲区 64 KiB，归档不整体进入内存或 JS 桥；两端使用本实验严格限定的平面已知长度 USTAR 子集和清单，不提供通用解包器。

## 实际校验与隔离

- 54 组全部取得完整成功回执；累计 11,052 项接收内容校验，其中手机端 5,526 个 SAF 新建文件均经写后回读校验，包含提供者实际名称检查与 EOF 检查。
- 三个 Windows 原目录仅打开读取；实验前后文件列表、大小、修改时间、身份与内容哈希一致。真实目录没有被写入、覆盖或删除。
- 只给全新基准目录取得 READ/WRITE SAF 授权，要求 authority 与精确 document ID 同时匹配；每轮输出位于新建 trial 子目录，不覆盖已有文件。
- 每轮清理仅删除本轮创建的输出 URI；实验结束释放该目录持久授权、删除专用私有缓存及本机/手机数据副本，并停止临时服务。源文件与原有只读目录登记不变。
- 授权 Activity 位于 src/debug、exported=false；已检查 debug 合并 Manifest 和 release 合并 Manifest，release 不含该入口。MIUI 通过先启动公开主页面再从前台打开内部测试 Activity，未改系统安全设置。

## 复验入口

控制端为[标准库 Python 脚本](../../scripts/experiments/transfer-benchmark.py)，手机端为 Android 仪器测试 TransferBenchmarkTest，需先执行 pnpm android:test 并安装 debug/test 两个 APK。此脚本只支持本轮形状的三个平面常规文件目录；拒绝重解析点和超出 USTAR 名称范围的输入。

```powershell
python -X utf8 scripts/experiments/transfer-benchmark.py `
  --bind <电脑LAN地址> --peer <手机Wi-Fi地址> --serial <ADB序列号> `
  --report .reports/transfer-benchmark.json `
  "<只读源A>" "<只读源B>" "<只读源C>"
```

启动后仅在系统选择器中授权新建的 SaveDataSync-NetBench 测试目录，并保持基准页面前台。没有 benchBase 参数时仪器用例跳过，不自动申请写授权或收发文件。输出 JSON/CSV 仅保存匿名统计。

## 适用边界

- 单个 LAN、API 33 设备、三个全量文件集合与三轮中位数；缓存、无线环境和实现差异会影响结果，不代表全部设备或严格冷缓存结果。
- 未测并行逐文件、xz、峰值内存/功耗和只改动少量文件的策略；不能据此直接确定自动压缩阈值。
- 写入校验是关闭流后回读，不是断电持久性或 fsync 验收；归档不会使整个目录更新自动具备原子性。
- 这是一套隔离的调试实验协议，不是版本 1 正式 HTTP、SAF 写入适配或同步产品交付。未覆盖实际覆盖/备份、空间不足、取消、断网、权限撤销或失败残留，WP-004/005/006/009/010 与 M-001 的剩余条件仍需分别实现验证。
