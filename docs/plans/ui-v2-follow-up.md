## 2. 已确认的设计决定

| 项目 | 当前目标 |
| --- | --- |
| 关闭覆盖前备份 | 全局和游戏单独设置都立即生效，不弹确认。传输计划关闭备份后开始传输时，仍保留现有确认 |
| 明暗背景 | 双端浅色页面采用原型浅蓝紫渐变；深色页面保持纯黑 `#000000`，包含 Android 启动及原生窗口背景。容器保留可区分的深色层次 |
| 圆角与控件 | 统一共用圆角，设置控件也纳入。根据实际显示和触控效果决定必要样式，不机械照搬补充稿“只设主色”的限制；保留已修正的 Stepper 原生外观 |
| 组件复用与点击范围 | 优先用 antd 已有组件。列表紧凑横条使用五等分的 Progress steps；详情使用带编号的 Steps，阶段名放在下方；圆形进度使用 Progress，游戏操作使用 Button；移动弹层继续使用 antd-mobile。取消传输使用普通按钮，按钮边界和点击范围都要清楚 |
| 游戏备份模式 | 保留“跟随全局设置”开关。跟随全局时，下方显示只读的全局值，另有修改全局设置的入口 |
| 桌面设置 | 回到原型的居中单栏；分组标题放在容器外；同组设置行之间加细分隔；标签在左，当前值或控件在右。行高参考 QQ，减少上下留白；长文字换行后，行高随之增加。语言、主题使用下拉选择，去掉设置项下方的说明小字，不使用 Segmented |
| 桌面菜单 | 参考用户提供的 QQ 图：选择器和菜单靠右对齐，选中项高亮并带勾选，边框与阴影清晰；宽度按内容和可用空间确定。桌面主题项继续叫“主题” |
| 手机设置菜单 | 仍点击整行打开菜单；菜单靠右，宽度按选项内容确定，不跟触发行等宽；宽度受视口限制，长选项仍要可读。当前项高亮并显示勾选，`DownOutlined` 使用与现有 RightOutlined 接近的小图标，和当前值在同一行；保留设置卡片原有边距 |
| 恢复预览 | 沿用传输计划的“新建 / 覆盖 / 保留”及统计含义，不改为“不变” |
| 游戏传输详情 | 从游戏进入时定位该游戏最近一次传输；无记录时显示该游戏空态。根页面任务横条仍进入对应活动任务 |
| 设备页 | 保留既有功能和布局，只同步色板、圆角及公共外壳 |

设置行的辅助说明按用户决定删除；删除说明小字时，错误原因、备份保存位置和卸载提示等独立信息仍要留在相应页面。桌面设置列以原型 `620px` 最大宽度作为起点，控件宽度改由设置行决定，不再使用固定 `160px` 的标签列，最终用四语言实际画面核对。

## 3. A 部分：纯 UI 与现有数据接入

A 部分可以查询现有受限 API、调整前端状态和组件参数，不改网络协议、Electron IPC 或 Capacitor 原生接口。

| 批次 | 改动 | 主要范围 | 完成条件 |
| --- | --- | --- | --- |
| A1 公共外观与设置 | 统一浅色渐变、深色纯黑、色板和圆角；桌面页头的返回按钮与标题放在同一行；手机使用悬浮胶囊导航；双端设置分组和菜单按第 2 节处理 | shared 设计变量及展示组件；双端 Shell、CSS、SettingsPage、ChoiceItem、设置表单 | 七类页面的明暗样式一致；桌面设置居中且标题放在容器外；手机菜单窄于设置行、靠右对齐并使用向下箭头；开关按现有设计立即保存 |
| A2 游戏列表与操作面板 | 手机的添加、导入入口移到页头；任务入口改为进度横条；双端把主操作与次级操作分组，四个次级按钮只保留图标和名称；顶部保留目录与关联摘要；统一“传输详情”入口 | 双端 GamesPage、GameActions、游戏弹层、App 页面参数 | 活动任务可直接打开；摘要绑定当前游戏；次级按钮为紧凑单行，备份内容在备份页读取 |
| A3 游戏设置与文件浏览 | 去掉游戏设置里重复的游戏名；两列独立滚动并使用固定列头；手机端文件名可换行，同时显示文件夹时间和差异数；桌面刷新按钮带文字，状态栏贴近底部；等待、扫描、就绪、取消和失败状态统一放进状态栏，两列不再重复显示错误 | 双端传输页、shared TransferComparison、布局 CSS、GameSettingsPage | 多文件与空目录均能操作；滚动一端不带动另一端；翻转方向、切换设备、筛选和返回后保留正确状态 |
| A4 详情与备份展示 | 手机详情的操作区固定在底部；桌面详情使用居中的窄栏；备份文件表补上类型图标；恢复预览保留传输计划统计；为 B 部分的数据预留明确的展示位置 | shared task/backup、双端详情及备份页 | 进行中只显示当前可用的操作；结束后先给结论，问题优先显示，成功详情收起；弹层和底栏不遮挡最后一行 |

A2 的桌面百分比可按需读取现有 `copyState`，手机已有 `currentCopy`。B1 完成前，电脑发送端只显示本机确知的传输进度；手机是否已写入、传输是否全部完成，暂时读不到。A 部分先做好这些展示位置，B 部分再接上缺少的数据。

A2 已按用户追加要求统一共用任务展示：列表使用 56px 高的紧凑横条，原生 `Progress steps={5}` 等分显示五个流程阶段，已完成为绿、当前为蓝、已知失败为红、后续为灰。旁边显示当前阶段及该阶段百分比，当前段按此百分比局部填充，50% 时只填半段；不按五等分估算总耗时。标题占用状态文字和箭头之外的全部可用宽度，超长再省略。详情使用带编号的标准 Steps，`titlePlacement="vertical"` 把阶段名放在下方，`percent` 显示当前阶段进度；圆形 Progress 同样显示当前阶段进度，计数未知时显示加载状态。出错后保留步骤条，已知失败阶段使用 `status="error"` 标红，前序显示完成，后序显示未开始。现有接口把终态阶段统一改为 `done`，用户明确选择在 B1 补齐真实失败阶段；缺少阶段信息的真实记录显示“没有记录失败发生在哪一步”。取消操作继续使用描边危险色按钮。

双端游戏卡片复用 3:4 渐变占位封面；接入图片前，封面里显示游戏名。下方名称只显示一行，超出时省略，另列关联摘要；悬停时只给封面轻微着色，整卡保持透明、无边框，文字背景不变。技术详情改为可点击展开、收起的圆角 Card；手机端长按复制全部，长按后松手仍保持展开，手势提示已删除；桌面端在内容右上角显示复制按钮。窄窗口下，路线和较长的技术文字可以换行。按用户最新要求，四个次级按钮去掉目录状态、备份数量、传输状态和保留文件小字，只显示图标与名称，高度从 52px 起；仅为这些小字服务的备份查询和四语言文案也已移除。游戏入口已经按项目筛选现有任务，没有记录时，空态显示游戏名；Android 原生按游戏查回更早记录仍由 B4 完成。A4 继续处理详情居中窄栏、固定操作区和备份展示。

## 4. B 部分：UI 与 API 一起调整

### B1 两端任务观察与桌面实际结果

- 现状：控制通道只回报准备、计划和最终 outcome；桌面详情读取 `SyncJobState` 本机角色，缺少远端角色及逐项结果。
- 补任务进度摘要和按任务读取最终结果的入口，覆盖电脑发起、手机发起以及两个传输方向。按设备、会话、任务 ID 和项目绑定匹配，保留双方独立角色；成功以接收端回读结果为准。
- 高频更新只传有界摘要，逐项结果按需获取，避免每次推送都携带完整计划和文件清单。页面重新进入时先读取当前快照，再接续更新。
- 把“已确认但手机尚未创建本机任务”的等待状态显示到详情里，避免进入页面后空白或显示上一项任务。
- 桌面详情、游戏进度横条、历史摘要和完成提示都读取同一份任务观察结果；发送已经结束而接收端仍在写入时，继续显示为进行中。
- 补任务的实际失败阶段，确保清理和终态更新不会覆盖错误发生的位置；重新打开失败任务时，仍能标红正确的步骤。用户已确认这部分数据调整留在 B1；A2 的编号步骤条与错误样式已经准备好，阶段未知时显示明确提示，不把所有错误都归到“写入”。清理失败仍单独提示。
- 影响：shared/control 及校验、桌面控制中心/任务登记/IPC/preload、Android 任务桥或事件、手机远程执行编排、双端适配器和详情。
- 验收：两个发起端、两个方向的组合；远端仍在写入、成功、部分失败、取消、连接中断后结果待确认、重新进入页面与清理重试。

### B2 目标备份策略与实际备份文件数

- 计划目前显示的是被写入端的策略；补上目标端保留份数后，两个方向都能显示“覆盖前备份 · 保留 N 份”。当前跨端项目描述只提供 `shouldBackup`，因此生产、序列化、校验和消费端都要一起调整。
- 成功摘要中的备份数量应来自实际已提交备份的摘要或清单。已有本机 `manifest` 入口优先复用；远端结果缺少数量时，补传大小有上限的元数据；计划里的覆盖数不能代替实际备份数。
- 备份轮换后旧记录已消失或结果读不到时，保留“已备份”的确知信息，数量按未知处理。
- 影响：shared/sync 描述、准备预览、Windows 项目接口及 IPC、Android 计划/备份模型与 TS 桥、SyncPlanSummary、SyncTaskSummary。
- 验收：全局/单独设置、开启/关闭、两个方向、备份数量与实际清单一致。

### B3 未完成备份占用大小

- 现有双端备份列表 `incomplete` 只有 ID。补充原生可取得的占用字节数，界面显示份数、占用大小及清理操作。
- 只统计应用私有的未完成备份，不为用户存档文件夹增加大小汇总；未知大小与零字节分开显示。清理入口仍只接受已有的不透明 ID。
- 影响：Windows backup-store/backup bridge、Android BackupStore/SyncBackupsPlugin、双端列表校验与备份页。
- 验收：零残留、多个残留、大小未知、部分清理失败及清理后刷新；只清理本次指定备份。

### B4 按游戏查询最近传输

- 桌面已有复制摘要列表，按本机项目 ID 选择最近任务，明确区分全局入口与游戏入口。
- Android 原生保有任务登记表，但 `current` 只返回全局最近项；补上按项目取得最近摘要、按 ID 查询详情的受限入口，这样页面重建时不必依赖 React 里的一份临时缓存。
- 选择任务、取消、清理和重新扫描时要使用对应的上下文；游戏 A 的页面不能显示游戏 B 的任务。全局的任务活动判断仍检查所有游戏，避免因为当前只筛选了一个游戏而放开写操作。
- 默认沿用现有的进程内任务留存期和资源上限；记录过期或进程重启后没有保留记录时，显示空态。本计划不保存磁盘任务历史，也不在重启后恢复任务。
- 影响：双端 App 导航与 TaskPage、Android SyncTransferEngine/SyncTransfersPlugin、移动 TS bridge/adapter/use-sync-tasks，必要时补桌面任务观察索引。
- 验收：先传 A 再传 B，分别打开两款游戏仍显示各自最近记录；未传输游戏空态；活动任务与另一游戏历史共存；留存过期与页面重建。

### B5 本机设备名展示

- 当前页面快照有对端名称，本机方向卡的 caption 为空；现有前端本机快照未提供可直接使用的本机设备名。
- 将已有系统设备名称通过受限本机元数据桥提供给两端，填入方向卡副标题；沿用系统名称/型号的现有取值规则。
- 影响：桌面本机快照/IPC、Android 本机信息插件及 TS 桥、双端 TransferComparison 参数。
- 验收：长名称、读取失败与两个方向；本机副标题不能使用对端的自定义名称。

接口调整先写明字段、角色、版本及失败含义，再同步修改生产端、校验逻辑和消费端。沿用双端同版交付的现有要求；已发布且封闭的 DTO 不能通过放宽校验来静默加入新字段。网络消息的版本方案在 B1/B2 接口设计检查点确定并记录，文件内容继续使用现有的 HTTP/tar.gz 流程。

## 5. 实施顺序

1. **A1**：先定公共外观、双端设置和菜单，以用户确认的效果确定后续页面的共同样式。
2. **A2 → A3 → A4**：游戏入口、文件区、详情与备份依次调整；每批单独核对双端实际画面。
3. **B1/B2 接口设计检查点**：明确任务摘要/结果、目标备份份数、版本与消息上限，并同步接口文档。
4. **B1 → B2**：先接实际执行状态，再补计划策略和备份数量；随后完成 A 部分暂缺的远端进度摘要。
5. **B3 → B4 → B5**：补残留占用、按游戏查询和本机名称；各项可单独验证，不改变写入算法。
6. **整体验收**：按第 6 节逐页、逐状态核对，更新相关 CR、当前实现说明与验收缺口。

A/B 是交付范围划分，不要求并行实施。A 完成后可以先单独检查外观，B 再按接口边界逐项实现。

## 6. 验收与验证

| 范围 | 验收内容 |
| --- | --- |
| 页面 | 游戏列表与操作面板、游戏设置、传输存档、传输计划、传输详情、备份与恢复、设备、应用设置 |
| 主题 | 浅色渐变；深色页面与 Android 原生背景纯黑；卡片、菜单、抽屉、弹层及禁用状态可辨 |
| 窗口 | 桌面常用窗口与较窄窗口；手机常用 360px、390px、430px 宽度，正常字号；长路径、长游戏名和长设备名 |
| 语言 | zh-CN、zh-TW、en-US、ja-JP；用较长的选项样例检查菜单扩展到更多语言时的布局，产品语言仍为这四种 |
| 设置 | 整行可点、菜单宽度与对齐、当前项勾选、开关立即生效、份数 1–10 和直接输入、跟随全局只读与跳转、重启持久化 |
| 传输 | 独立滚动、进入/返回文件夹、翻转、换设备、筛选、等待、取消扫描、失败重试、同一次扫描生成计划、冲突禁用 |
| 任务 | 两端发起和两个方向，活动/成功/部分失败/取消/待确认/清理失败；接收仍写入时保持进行中；按游戏定位与空态 |
| 备份恢复 | 时间线、文件类型、策略状态、实际备份数、残留大小与清理、弹层/右侧原地预览和结果；恢复统计沿用传输计划 |

实现阶段运行 `pnpm check`；桌面变更文件执行 `antd lint --format json`。Android 构建使用现有入口；涉及原生代码时运行相关的既有原生检查。按改动范围运行现有 shared、desktop、mobile 测试。交付界面时直接打开并保留可交互的浏览器预览，按用户要求不再截图；不新增长期 DOM/CSS/快照测试。接口改动确实需要长期测试时，先列出稳定的边界用例和理由，确认后再加。
