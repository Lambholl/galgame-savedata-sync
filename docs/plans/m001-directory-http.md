## 2. 能力与数据边界

| 层 | 设计职责 | 限制 |
| --- | --- | --- |
| 共享模型 | 设备描述、目录引用、条目元数据、能力、任务进度、错误与传输回执 | 不导入 Electron、Node 文件 API 或 Android 类型；内容不通过 JS 桥传递 |
| Windows 本地适配 | WP-002 选择目录、登记 rootId、读取当前层及原生只读流；WP-009 另实现新文件暂存发布 | Renderer 仅调用受限 preload；网络端不能传入主机绝对路径；只读目录没有写入/删除 API，后续写入只在独立测试目录验证 |
| Android 本地适配 | Java 插件通过 SAF 获取只读目录授权、恢复、查询当前层及原生读流；新文件写入另由 WP-010 实现 | content URI 作为平台内部引用，不能转成磁盘绝对路径；每次恢复与操作核实授权和提供者能力；root 不替代系统授权 |
| 双端归档 | WP-012/WP-013 在私有缓存准备原文快照、打包受限 USTAR/gzip1 或完整解包校验 | 归档成员名为 fileId，目标映射单独验证；有限缓冲及硬限计数，不发布目标或实现网络 |
| Windows HTTP | 描述设备/会话、读取登记目录、准备/发送归档、接收归档、查询/取消任务 | WP-004/005 编排归档及发布；仅处理已登记根与获写授权的独立夹具，不提供全磁盘接口 |
| Android HTTP | WP-006 原生编排双向归档、网络、校验及 SAF 发布，向 JS 发出进度和实际结果 | 复用 WP-013/WP-010；不传 Base64；离开前台取消，返回后核实当前状态 |
| 验证界面 | 展示源/目标、当前读取时间、真实属性、连接及任务结果 | antd 与 antd-mobile 分别适配；文件夹大小显示“—” |

目录引用与地址分离。Windows 和 Android 均在安装内生成并保存稳定 deviceId；连接地址可修改，不能作为目录引用的主键。M-001 仅验证身份读取和本地保存，设备关联与换址迁移的完整流程由 M-002/M-003 完成。

条目采用平台不透明 entryId 和显示名称，不以显示名称拼装可访问路径。目录为空、条目不存在、授权失效、读取失败分别表达。文件大小未知使用 null，不能用 0 代替；文件夹大小固定 null。修改日期是条目自身的时间戳，未知使用 null，不用于选择方向。

列目录只查询当前层；用户展开时再查下一层，不为文件夹大小遍历后代。提供者能力应区分支持、不支持和未知；实际操作结果优先于预先声明。Android 不承诺保留原修改日期或提供目录级原子替换。

## 3. 文件往返流程

### 3.1 读取与连接

1. 用户在 Windows 本机和 Android 系统选择器分别选择测试目录；取消选择不清空既有有效引用。
2. Windows 主进程显式启动测试 HTTP 服务并显示监听地址、实际端口和状态；本期不引入 mDNS。端口冲突必须显示失败，服务随应用退出释放。
3. Android 前台通过手动 IP/端口读取设备描述，确认协议版本，再读取 Windows 已登记根目录的当前层条目。
4. 本地授权与远端地址分开保存。Android 重启后重新核实授权；失效时要求重新选择，不能显示为空目录。

### 3.2 Android → Windows

1. 用户选择 Android 显式文件集合及 Windows 已有目标父目录/新文件名映射，生成本次 transferId；原生层私有暂存源原文并实测长度/哈希，生成稳定 tar.gz 及清单，核实可观察源变化。
2. POST /v1/transfers/uploads 先登记清单和目标，Windows 检查会话、写授权、冲突、资源和单次 ID；201 只表示任务已登记。
3. PUT content 发送唯一归档；Windows 私有暂存、校验完整压缩体及所有原文后才逐项非覆盖发布。202 只表示等待异步校验/发布，成功项必须完成最终回读；首次发布失败停止后项并保留实际结果。
4. 通过 GET 任务状态取得逐文件终态。响应丢失只查询/核实，不重放 POST/PUT；目标未知不能当成未写入。字段、期限及错误详见批量契约。

### 3.3 Windows → Android

1. POST /v1/transfers/downloads 指定 Windows 文件集合，服务异步准备私有原文快照和归档，ready 后 GET manifest；清单/原文不能作为历史同步基线。
2. Android 验证清单、本地已有目标映射和写授权，再 GET content；先完整校验归档及全部原文，后调用 SAF 发布，不将归档路径直接展开至目标。
3. SAF 新建后核实实际名称、内容/EOF 和最终条目，逐文件反馈；改名/同名歧义/无法保证不改写已有文件时拒绝或待确认，不能假设排他创建。
4. Windows 的 sender sent 只表示发送完成，手机 receiver succeeded 才表示目标全部发布。失败或取消只尝试清理本次确知新建的未完成项，保留已成功文件与原有文件，列出残留。

### 3.4 中断与结果

批量契约区分 sender/receiver：sender 终态 sent 不代表目标发布，receiver 才能报告 succeeded，双方均可失败/取消/待确认。running 阶段包括 preparing/ready/awaiting-content/transferring/verifying/publishing/cleaning，分开源读取、归档传输、原文校验和已发布字节；未知总量不计算百分比。逐文件结果可为成功、失败、取消、未尝试或待确认；完整约束见批量契约第 6 节。

Android 离开前台时停止新操作、取消网络与文件任务，并通知 Windows 取消未发布的接收。取消与提交竞争时，以可核实的实际终态为准，不承诺远端已完成文件自动回滚；确认不了时显示待确认。Windows 暂存和任务状态限定本次会话，设置到期清理，不保存长期传输账本。服务重启后查询不到旧任务时，重新读取当前目录核实；不得根据旧状态自动覆盖或续传。

手机与电脑在同一局域网进行 HTTP 验收。ADB 用于安装调试包、查看日志及检查运行状态；不以 adb push/pull、端口转发或 reverse 代替实际文件传输验收。不新增 Android 后台服务、任务调度或保活机制。

## 5. 验证与完成条件

- 针对性检查优先：共享契约、Windows 临时目录与 HTTP 集成、Android 原生编译与提供者行为；测试覆盖关键失败边界，不镜像实现。
- 受影响实现包完成后执行 pnpm check；Android 原生有改动时补原生构建；新增或变更依赖时执行现有 npm、Android 依赖与工具链安全检查。网络/解析失败不能视为审计通过。
- Android 真机检查前准备 ADB；Windows 本地实现和 Android 原生构建无需连接设备。用户开启调试并确认设备授权后，才按对应验证范围安装和写入合成夹具。
- 设备矩阵至少包含 API 29 真机及一个较新 Android 版本真机；只有一台设备时可先验证该设备，未覆盖的平台继续标记为缺口。模拟器只补充兼容性检查。
- 用合成空文件、中文/空格文件名、嵌套目录和大于单次缓冲区的文件验证，不将真实存档作为故障注入材料。
- 具体场景见[测试用例](../../.project-memory/testing/test-cases.md)。目录读取与 HTTP 往返成功只是 M-001 结果，覆盖复制、镜像、备份、自动发现和产品级验收仍为 pending。
- M-001 完成条件：共享契约、双端读取、归档、目标发布、HTTP、验证界面均实现及检查通过；WP-008 两个平台真机矩阵通过；双向接收内容与本次预期 SHA-256 一致，正式归档/资源/故障矩阵通过；失败和取消不伪报成功，前台与不递归统计目录大小边界成立。缺少任一项时保留未完成状态。

## 6. 拆分与恢复规则

出现以下任一情况，停止扩大当前包，先在工作包登记中拆分并更新依赖：

- 同一包需要同时修改共享协议和两个平台的核心行为，且无法分别验证。
- SAF 提供者差异要求独立的能力协商、最终写入或残留恢复设计。
- 上传、下载或生命周期验证无法在同一包给出明确结果：按方向或生命周期边界拆包。
- 发现实现必须引入新依赖、变更持久配置格式，或改变既有产品范围；先记录影响和验证方案，需要改变已确认需求时再取得确认。
- 包内缺少设备时，只推进不依赖设备的实现与自动检查；将真机验收保持 pending，不把缺少证据标成通过。

编号只能在高水位之后分配。保留原包范围、已完成部分和剩余交接，新包只接收明确拆出的范围；不重复承诺同一交付物。每个包启动、阻塞、检查点及完成时更新 INDEX 与登记表。完成时先更新当前实现事实与证据，再调整工作包状态；未经授权不提交 Git。

## 8. 技术参考

- [Android SAF 与目录持久授权](https://developer.android.com/training/data-storage/shared/documents-files)：用户选择目录并以 URI 访问；平台存在可选择目录限制，授权丢失需重新处理。
- [DocumentsContract.Document](https://developer.android.com/reference/android/provider/DocumentsContract.Document)：元数据及操作能力由提供者表达，未知属性不能伪装为有效值。
- [Android 真机调试](https://developer.android.com/studio/run/device)：ADB 用于部署和调试；项目验收另要求实际局域网 HTTP。
