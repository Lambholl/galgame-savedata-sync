## 1. 结论与范围

2026-10-28 完成 Windows 桌面应用与 Android API 33 真机的满额 1 GiB 双向局域网 HTTP 验收。结合既有 Android 10 与较新系统、目录授权恢复、后台继续、取消及独立界面的验收，M-001 的目录与新文件往返范围满足收尾条件。

本轮使用独立合成目录，原文为四个各 268435456 字节的随机文件，合计 1073741824 字节；随机内容用于避免高压缩率掩盖网络与存储开销。Windows 使用正式编译后的 Electron 入口、窗口及原生模块，仅隔离本轮配置；Android 使用重新编译安装的 debug APK、实际 SAF 与原生 HTTP。ADB 负责控制和采样，归档内容通过实际局域网传输。

用户明确取消功耗计算，并将磁盘耗尽故障注入移出本轮。每次传输提前检查可取得的剩余空间已经作为 REQ-020 实现。

## 2. 实测结果

耗时从发起任务到接收端成功，包含准备、压缩、网络、解包、逐文件发布、回读与清理，以及约一秒的终态查询误差。

| 指标 | Windows → Android | Android → Windows |
| --- | --- | --- |
| 原文 | 1073741824 字节，4 文件 | 同一组 1073741824 字节，4 文件 |
| tar.gz | 1074070003 字节 | 1074070008 字节 |
| 完整流程耗时 | 87.526 秒 | 215.400 秒 |
| 接收终态 | succeeded，4 项成功 | succeeded，4 项成功；Android sender 为 sent |
| Windows 主进程采样 RSS 峰值 | 170.625 MiB | 162.520 MiB |
| Windows 各应用进程工作集合计采样峰值 | 429.031 MiB | 416.875 MiB |
| Android 主进程采样 RSS 峰值 | 231.535 MiB | 223.691 MiB |
| 采样数量：Windows / Android | 87 / 77 | 215 / 188 |

Windows 每秒用 Electron `app.getAppMetrics()` 与 `process.memoryUsage()` 采样；各进程工作集合计包含共享页面的重复计数。Android 约每秒通过当前应用 UID 读取主进程 `/proc/<pid>/status`；该数值覆盖原生传输所在主进程，独立 WebView 渲染进程另计。Android 主进程高水位为 234.684 MiB；Windows 主进程在本次应用生命周期中的工作集高水位为 185.617 MiB。采样期间 ADB 错误为零。

外部 SHA-256 核对覆盖 Windows 原始文件、Android 接收文件、Windows 回传文件，四项全部一致。Windows 源大小和修改时间与下载清单一致；Android 源大小和修改时间与上传清单一致。最终目标恰好四个文件，双方任务缓存仅留下根所有权标记，任务与发布候选均已清理。

反向流程的逐文件发布明显比网络发送耗时长。本轮保留测量结果，后续若优化发布性能，应继续保留完整校验、非覆盖发布和明确结果。

原始采样、请求/终态、清单及核对结果保存在 Git 忽略的 `.reports/wp008/`；其中 `summary.json` 为汇总，`download-result.json`、`upload-result.json` 为完整回执。本文保存可进入 Git 的验收结论，不记录设备标识或本机地址。

## 3. 每次传输的空间预检

- Windows 接收登记前检查私有缓存的“压缩体 + 解包原文”需求，并检查本批最终文件总量；缓存与目标同卷时合计两部分峰值。余量不足返回 `insufficient-space`，拒绝登记接收。
- Windows `checkReceiveSpace(manifest)` 返回仅供原生使用的卷标识与缓存需求；`checkTarget(request, requiredBytes?, privateSpace?)` 默认检查单项，也接受整批总量与同卷缓存需求。检查不预留磁盘，写入期间继续逐块检查。
- Android 在打开下载内容流前检查私有缓存，并根据 SAF 提供者根的容量和子文档关系检查本批目标总量；容量未知或提供者不开放查询时继续按未知处理。目标实际写入前仍通过文件描述符检查容量；SAF 提供者与缓存是否共用物理存储可能无法提前识别。
- 发送端在本地准备及实际写入私有快照/归档时检查可用空间；未知长度按实际读取计数。应用不把一次预检当作空间预留，传输期间其它程序占用空间时仍按实际写入结果结束任务。
- Windows 使用既有磁盘能力注入将可用容量设为零，确认目标和私有缓存均在预检阶段返回 `insufficient-space`；探针没有填满磁盘。Android 新路径通过构建、既有原生检查及本轮真机往返验证，未知容量兼容行为保留。
