## 目标与依据

将目前堆在验证页上的操作整理成“设备、游戏、设置”三个入口。一个游戏可以关联多台设备，每台设备为这个游戏保存自己的一个目录。点游戏卡片后，先看到该游戏的操作面板，再进入传输、目录设置或备份恢复。传输页选择本次对端，带入本机和该设备的目录，并排显示两端文件。

原型位于 [index.html](index.html)。顶部画幅、主题、页面、状态菜单只供审阅，数据均为示例。视觉参考来自用户提供的 `ui-designs` 截图：游戏卡片、游戏操作弹层、主导航；双列文件视图参照用户提供的 MT 管理器截图。采用项目现有的 Windows Electron + antd、Android Capacitor + antd-mobile 技术栈。当前 M-001 仍以独立测试目录中的新文件传输为边界；覆盖、镜像删除、项目映射和备份恢复按后续里程碑接入。这份文档描述目标界面，标记为草案。

## 页面结构

| 入口 | 内容 | 主要动作 |
| --- | --- | --- |
| 设备 | 本机服务、已保存设备卡片、每台设备的地址与连接状态 | 添加、连接、断开、修改或移除设备；电脑开启服务接收手机连接 |
| 游戏 | 游戏卡片列表与当前传输入口 | 添加游戏，点卡片打开操作面板 |
| 设置 | 跟随系统的主题、帮助与版本号 | 查看连接或授权问题 |

点游戏卡片后，Android 打开底部弹层，Windows 打开居中弹窗。面板的主动作是“传输存档”；次级动作是“目录设置”“备份与恢复”“本次传输”“移除游戏”。“两端文件”直接放进传输页，不在面板里另开一页。游戏页只展示连接状态、活动任务和游戏卡片，不写操作说明文案。

## 设备管理与游戏关联

设备页用卡片展示每台已保存设备的名称、类型、地址与独立连接状态。一台手机可以保存并连接多台电脑，一台电脑可以保存并接收多台手机连接。手机添加电脑地址后，可分别连接或断开；电脑保留本机服务入口，手机连接后显示为设备卡片。电脑端离线手机显示“等待手机连接”。设备卡片内的“管理”用于改名、更新地址或移除设备。原先的“连接后去游戏”和“电脑地址变了”说明卡片删除。

设备记录和游戏关联分开：一台已保存设备可以关联多个游戏，一个游戏也可以关联多台设备。游戏目录设置列出这个游戏已关联设备的名称与目录，可从其余已保存设备中继续关联。解除某个游戏的关联不删除设备卡片，也不影响其它游戏。全局移除设备时明确提示会移除其游戏关联，保留本机游戏目录和存档文件。

传输页的“对端设备”只列出当前游戏已关联的设备，同时标出连接状态。每次任务只在本机与选中的一台对端之间执行；切换对端时更换远端目录、清除旧浏览位置并重新预览。所选设备断开或被解除关联后，要求重新选择；不自动替换成另一台设备。未关联或缺少目录的设备给出补齐入口。

多台设备可同时在线。传输先沿用当前的一次一项限制，这是本设计的建议，避免多台设备同时写同一个目录。任务启动时固定游戏、对端设备、方向和两端目录，页面切换不更改已有任务。活动任务涉及的设备暂时禁用断开、移除和解除关联；修改地址或更换目录要先结束任务。停止电脑服务时提示将断开所有手机，并取消当前任务。

实现时按稳定设备 ID 保存关联，IP 地址是可更新的连接信息。更新地址后仍关联原设备；名称相同不作为同一设备或同一游戏的依据。跨端游戏标识、目录映射交换和多会话管理需要补充接口设计；当前原型用示例数据演示这些关系。

## 关键交互

### 游戏目录

一个游戏在每台设备上各对应一个目录。电脑通过电脑应用修改本机目录，手机通过手机应用修改本机目录。目录设置页显示本机目录和所有已关联设备的目录，本机有“选择目录”操作，远端只显示名称与目录路径。删除“在电脑设置”“在手机设置”标签。断连时仍显示已保存的游戏和本机目录；远端状态需要重新连接后核实。

删除“保存配置”按钮。游戏名称修改完成并离开输入框时保存；本机目录选择成功、关联或解除设备时立即保存。保存失败时保留输入并提供重试。原型在内存中演示名称与设备关联的保存，系统目录选择器以说明面板展示。

添加游戏时先设置本机目录。两端配置齐备后才能预览跨端传输；缺少一端时，指出要到哪台设备补齐。更换任一端目录后，下次传输须重新读取并预览。删除游戏配置与删除存档文件分开：移除游戏只移除映射，不删除目录中的文件。

### 传输存档

从游戏进入时已经知道本机目录和各关联设备的目录。页面从上到下为：本次对端设备、两端文件、同步方向、两项紧凑开关、底部固定“预览本次变化”。两个开关分别是“删除目标端多出的文件”和“覆盖前备份”；默认分别关闭、开启。备份保留最近 3 次。开关旁只显示名称与状态，后果在预览页说明。

方向为“电脑 → 手机”或“手机 → 电脑”，由用户明确选择。方向切换后，两列的“源”“目标”标记同步变更。关闭删除时，目标独有文件保留；开启删除时，预览列出要删除的目标文件。预览按新增、覆盖、删除或保留显示文件与数量，并显示这次是否备份。确认执行前重新检查当前两端目录；检查结果变化时更新预览并要求重新确认。目录授权失效、断连或同名类型冲突时停留在当前页，给出对应操作入口。

传输进度和文件结果从游戏的“本次传输”进入。发送完成、目标写入成功、结果待确认和临时文件清理失败分别显示，避免把发完文件当作写入成功。Android 切到后台后，已有传输由持续通知保持，返回页面显示当前任务。

## 两端文件视图

电脑列与手机列在手机和桌面上始终并列；窄屏各占一半，不切换标签页。每列有设备名称、当前路径、源/目标标记、独立滚动区域和“上一级”。点一列的文件夹只改变这一列的位置。文件名占主行，大小与修改时间紧凑排列在下方；时间精确到分钟，例如 `2026-10-27 08:32`。窄列将大小与时间分行，确保分钟完整可见。长名称在列内截断，点文件可看完整名称与属性。文件夹大小用“—”，未知文件大小标“未知”。空目录、授权失效与断连只改变受影响列的内容，另一列仍可查看。两端文件浏览不单独出现在游戏操作面板。

## 备份与恢复

游戏操作面板提供“备份与恢复”。电脑应用列出本机电脑持有的该游戏备份，手机应用列出本机手机持有的备份。点击一份备份后自动显示其时间、目标目录以及将新增或覆盖的文件；用户确认后才恢复。删除“预览恢复”按钮和“最近 3 次”展示文案，保留既定备份保留策略。恢复结果按文件显示。若备份实际保存在另一台设备，需要到那台设备操作。备份位于独立备份区，不与游戏存档目录混列。

恢复所需的文件写入、失败清理、覆盖前保护与 UI 状态须在后续实现设计中明确；本次只确定入口与可见流程。原型的备份日期和恢复结果是展示样例。

## 状态与平台差异

- Android 用底部三项导航与游戏底部弹层；Windows 用左侧三项导航与居中弹窗。主要动作名称一致。
- 正常、空目录、断连、目录授权失效、同名冲突、结果待确认、清理失败都有独立展示。顶部“状态”菜单可逐个查看样例。
- 主题默认跟随系统。Android 暗色页面及原生窗口背景按现有需求使用纯黑 `#000000`；原型顶部的主题开关只用于检查设计稿。
- 操作文字只放读者要作决定的位置，例如删除清单、恢复预览、服务停止时的任务提示。技术任务 ID 和分阶段字节数收进详情。
